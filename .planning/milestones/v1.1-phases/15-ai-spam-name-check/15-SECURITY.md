## What leaves the server (data egress, verified in code)

One HTTPS `POST https://api.anthropic.com/v1/messages` per judged string, built by `cn:68-84` and `cr:123-158`:

| Part | Content | Where fixed |
|---|---|---|
| Headers | `x-api-key`, `anthropic-version: 2026-10-21`, `Content-Type`; Go's default `User-Agent`; the TCP/TLS source address | `cc:228-232` |
| URL | the constant `https://api.anthropic.com`; no env or config overrides it (`memberReqAIEndpoint` is reassigned only in tests, `ai:114`) | `cc:26`, `ai:114,155` |
| `model` | `ANTHROPIC_MODEL`, validated by `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` | `cc:56-62`, `fuku/config/config.go:595-603` |
| `max_tokens` | 128 | `cn:13` |
| `system` | the code-owned constant `NamesInstruction` | `cn:32-46` |
| `thinking` | `{"type":"disabled"}` (accepted by Haiku 5.5 at effort `high` or below; the bot sends no effort, so the default `medium` applies) | `cr:132-138` |
| `tools` | exactly one, `report_spam_probability`, `strict: true`, schema `{spam_probability: number}`, `additionalProperties: false`, `required` | `cr:95-107,149-154` |
| `tool_choice` | forced to that tool, `disable_parallel_tool_use: true` | `cr:128` |
| `messages` | one user message, one text block: `json.Marshal` of `{first_name, last_name, username}`, cut to 64, 64 and 32 runes | `cn:60-83` |

Never sent, by construction: a chat ID, user ID, group title, bio, message text, photo, join time, any other group or member data, or any sampling parameter (`temperature`, `top_p` and `top_k` return 400 on the `2026-10-21` API version, and none is sent). The `request` struct has no `metadata` field (`cr:24-33`). The strings are the canonical form (`canon:58-72`): invisible runes dropped, NFKC applied, whitespace collapsed, username lower-cased without "@".

Held by `TestClassifyNames` ("sends the names request": decodes the body, asserts one tool, the forced choice, only `spam_probability` in the schema, no image block, no sampling field), `TestClassifyNamesInjection` (hostile names arrive as data, the system text, tools and blocks are unchanged), and `TestMemberReqAIRequestIsMinimal` (`memberreq_ai_sweeps_test.go:169`: the bodies the bot's own call path sent). All pass.

What the answer can influence: `parseVerdict` (`cresp:64-109`) accepts only `stop_reason == tool_use`, a `tool_use` block named `report_spam_probability`, and a finite `spam_probability` in 0..1 (`cresp:96`). Refusals are `ErrBlocked`, so they are never a breach and never cached. Extra keys in the tool input are ignored (`toolInput` reads one field, `cresp:57-59`). The bot reads nothing else from the model, so a name that talks the model into any other output at most changes the probability of the attacker's own string. A prompt-injection name cannot change the tool schema, the tool, the validation or any other member's verdict. Live model behaviour against injection names is not provable offline: it is owner check 1 of `15-SPIKE.md` (10 injection names in the spike's names mode).

**What an attacker with many accounts can do to the global budget.** Spending 400 units in an hour makes `memberReqAIReserve` answer capped for every group until the next UTC hour. The effect is a sticky unknown, the safe direction: nobody is punished, the AI row cannot punish anyone, and the weaker name rules still apply (D-22, T-15-14). The cost to the owner is that spam accounts with distinct names escape the AI rule for up to an hour, and that every member who joined while the rule was live and has not yet been judged stays unjudged (their marker stays). Their messages then cost runner jobs, which was SEC-02 and is now stopped by the refusal latch (one job per chat per replica, then none until the hour ends). Cheaper variant: 20 accounts in one group disable that group's AI check for the hour (100 units). The hour windows are aligned to UTC hours, so an attack at minute 59 and minute 00 can spend two windows (up to 800 calls in about two minutes). The attacker's cost is the accounts and their joins; no wrong punishment results.

## Where a spammer escapes (honest list of the accepted limits)

None of these punishes an innocent person; each is a case where the rule does not act.

1. **Already in the group when the rule was switched on:** first recorded with no call (baseline), judged only after a rename (D-02, D-21; AR-01).
2. **Dormant for over 180 days** (baseline lapse, nothing refreshes it), or a joiner whose join judgement was unanswered and who stays silent for over 30 days (marker lapse): first-sighted again and baselined with no call (AR-01).
3. **No Redis, a failed marker write, or a join the bot never saw** (captcha failure, lockdown ban): a real new member is baselined at their first message and unjudged until they rename (AR-01).
4. **Check on join off:** new members are judged at their first message; a silent joiner is not checked. The three AI card texts now say "when they join or at their first message" (SEC-04, fixed).
5. **The model:** a probability below 0.9 (false negative); non-determinism with a lucky first roll cached 24 hours; refusals on adult-content names (never cached, never caught); names tuned against the public instruction text in this repository; homoglyph or digit variants, which are new strings and each cost one of the account's 5 calls an hour (AR-02, AR-05). A muted spammer can use the same variants with "I fixed it" to try for a pass (5 an hour).
6. **Case-only renames** share the baseline and the verdict key, so the casing judged first decides both for 24 hours (RV-IN-01, AR-04).
7. **System states, all sticky unknown:** an exhausted hour (account, group or fleet), a full gate, a paused breaker, a rejected key, Redis down. The weaker name rules still act; the stricter AI action does not (D-22, AR-11, AR-12). While the group or fleet allowance is spent, the gate stayed full or the counter failed, the watcher also starts no job for a marker holder (the refusal latch, SEC-02, AR-18), so a member whose string has a cached breach is judged by the first message after the latch ends.
8. **A weaker-rule hold** (RV-NEW-01): a spammer who breaks a weaker rule while the AI answer is a sticky unknown is held for that rule only. Their hold has no bit 128, so the AI rule is not asked while the hold lives, and a Warn hold lasts as long as the weaker violation does (AR-07).
9. **The baseline rule, in both halves:** a member whose baseline equals their names and who has no marker is satisfied in the watcher and passes in the job even when another account's judgement of the same string cached a breach, so a pre-existing spammer who shares a string with a judged account is not caught by the collision (SEC-01, fixed; the rule, not a gap).
10. **Exempt:** approved members, administrators, bots, Telegram service accounts, a pending captcha, a held member (no lookup unless the hold carries bit 128). A basic group is never screened. The per-chat cap of 10 punishments a minute (Phase 13) pauses punishments in a large raid.
11. **Not read at all:** bio, photo, messages, the account's age. The rule judges three strings.
