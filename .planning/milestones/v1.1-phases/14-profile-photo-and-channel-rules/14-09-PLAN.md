## Phase Goal

**As a** group owner, **I want to** require a profile photo and, in a channel's comment group, a subscription to that channel, **so that** throwaway accounts and outsiders are screened too, without anyone punished because a lookup failed.

After this plan the Requirements page tells the owner when a rule cannot work in that group (no linked channel, the bot not an administrator there, a basic group), says so in words on the page and on the rule's screen, and offers Off alone for a channel rule that cannot be linked.

- The basic-group line replaces the channel lines (a basic group cannot have a linked channel); a basic group is read from `p.group.Type == "group"`, a value both menus already hold, so it costs no call (UI-SPEC section 2).
- The page lists a problem only for a rule that is not Off; a rule screen always shows the line for its own rule, because the screen exists to explain (UI-SPEC P14-A1). With every rule Off a basic group shows the all-off line and no 🚫 line.
- The channel screen draws `[Off]` alone for "no linked channel found" and "basic group" only; the "could not check" state keeps both choice rows (the press decides, plan 14-10).
- Status icons are code-side prefixes: `🚫 ` for a condition, `❔ ` (the page's existing unknown mark) for an unreadable status; no template contains either.

The settings family `go test -tags testtools -race -count=1 -run '^(TestSettings|TestLoadSettings)' ./fuku/modules ./fuku/i18n` (about 4.5 minutes) runs once at the end of this plan.
