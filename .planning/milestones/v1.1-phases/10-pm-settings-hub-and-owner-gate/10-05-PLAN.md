## Phase Goal

**As a** group owner, **I want to** open my groups' settings from the bot's private chat and decide whether my admins may change them, **so that** I control who configures the bot.

After this plan, the owner-only default is real on in-group `/settings` (with its anonymous re-entry) and on every button press: an admin who is not the owner cannot open the menu in the group or use a menu already open, while the owner and (when the switch row is on) allowed admins work as in v1.0. The `/start settings_<chat id>` deep link gets the same gate in plan 10-11, which was split out of this plan in revision 2 so that each plan stays well inside the context budget.

## Planner assumptions (flagged, non-blocking)

- **A1 (deleted-account owner):** for a group whose owner deleted their account, `getChatAdministrators` is assumed to return a creator entry with first name "Deleted Account", no last name and no username. `settingsCreatorGone` treats that entry as no live owner, so admins are let in (D-15). It reuses the existing name test `isDeletedAccount` (`fuku/modules/misc_extras.go:40`: an empty name, or "Deleted Account" in any case) and adds two conditions, no last name and no username, so the repo keeps one definition of a deleted account's name. The stricter rule is needed because the gate lets admins in on this answer while `isDeletedAccount` only decides a display: a deleted account has neither field, and a live owner who merely names themselves "Deleted Account" but keeps a username or a last name still counts as the owner. Per the orchestrator, there is no human-verify checkpoint for this (the research suggested one); the live confirmation is a manual, non-blocking check listed in the phase SPIKE file (plan 10-10). If the real entry differs, the gate fails closed: admins of such a group get `settings_check_failed`, never wrongly let in.
- **A2:** a bot that is only a plain member is assumed able to call `getChatAdministrators`; if it is not, gated admins get `settings_check_failed` (fail closed). Manual, non-blocking check.
- **A4:** an anonymous creator's `getChatMember` still reports `creator`; otherwise the anonymous owner is gated like an admin (fail closed).
- **Gated Close (UI-SPEC unresolved):** every press is gated, Close included, as MENU-11 and "when unclear, refuse" require; a gated admin deletes the stale menu with Telegram's own delete. Accepted limit.
