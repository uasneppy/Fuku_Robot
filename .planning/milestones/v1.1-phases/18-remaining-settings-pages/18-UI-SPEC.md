# Phase 18 - UI Design Contract

> Visual and interaction contract for the **six new pages of the settings menu**: Warnings, Switches (Reports, AI spam,
> Auto-approve), Language, Log channel, Anonymous admins and Locks (paged), their Main-grid cells and state lines, every
> status line, notice and alert they show, every new callback with its worst-case size, every new string with its key
> and ceiling, and the checks that prove it.
> Generated by gsd-ui-researcher; to be verified by gsd-ui-checker.
> Upstream: 18-CONTEXT.md D-01..D-14 (provisional owner defaults, treated as locked here; the UI decisions are D-04 to
> D-12), REQUIREMENTS PAGE-01..PAGE-06, PAGE-10, PLAT-05, ROADMAP Phase 18, the APPROVED Phase 16 and Phase 17 contracts
> (`16-UI-SPEC.md`, `17-UI-SPEC.md`, whose message anatomy, text styling, status icons, row budgets, size budgets,
> copywriting register and numbered amendments and assumptions this file reuses and continues: M1 to M33 stay in force and
> this file continues with **M34**, and A16-A* and A17-A* stay in force and this file continues with **A18-A1**),
> AGENTS.md (Callbacks `settings|v1`, Handlers, Permissions, the Captcha, Antiflood, Member requirements and Deletion page
> bullets, "One setting, one code path") and the code of `fuku/modules/settings_pages.go`, `settings_menu.go`,
> `settings_card.go`, `settings_captcha.go`, `settings_antiflood.go`, `settings_deletion.go`, `settings_staff.go`,
> `warns.go`, `reports.go`, `aispam.go`, `greetings.go`, `language.go`, `logchannels.go`, `admin.go`, `locks.go`, their
> repositories (`fuku/db/warns`, `reports`, `aispam`, `greetings`, `lang`, `logchannels`, `admin`, `locks`),
> `fuku/utils/chat_status` and `locales/en.yml`.

This phase has no web screen. Everything is a Telegram message in HTML parse mode plus an inline keyboard, on the one
surface the settings menu always had: the menu message, private or opened in the group, edited in place. There is **no
group-side text** in this phase: no page posts into the group (the Log channel page's category change posts the same
`#SETTINGS` entry to the log channel that `/log` and `/nolog` post, nothing else, A18-A10). Anything not restated here
is unchanged and applies to the new pages: the message anatomy, text styling, the press pipeline (`settingsPress.verify`,
owner gate at step 4b, one answer per press), the rights model, the cannot-open edit, "never name the Staff Group" (D-21,
D-32 of the menu) and the Phase 11 to 17 limit tables.

Each page is **one `registerSettingsPage` call from its own file** (`settings_warns.go`, `settings_switches.go`,
`settings_language.go`, `settings_logchannel.go`, `settings_anonadmin.go`, `settings_locks.go`); `settings_pages.go` is
**not edited** (D-03). The only framework edit is two appended right constants (M35, A18-A4) in `settings_menu.go`.

## Message Layout (replaces Spacing Scale)

The Phase 9 anatomy stands: a header line (`settings_header` with the page name), the group line (`<b>title</b>
<code>id</code>`), one blank line, the body lines, and one blank line plus the footer when there is a notice. This phase
adds one changed screen (Main) and six page screens (the Locks page in two pages). The two Phase 16 slots stay: a
**status slot** (one blank line, then one line) where a page has a status line, and a **foot notice** (`⚠️` for a
refusal or a failure, `✅` for a success) for the press that just ran.

**Order and why.** `Order` values: Warnings **42**, Locks **44** (between Antiflood 40 and Welcome 50, so the protection
pages sit together: Staff, Lockdown, Captcha, Antiflood, Warnings, Locks), then Switches **86**, Language **87**, Log

Welcome is an even number, so **Welcome|Goodbye, Rules|Requirements keep their pairs** and only Deletion's partner
changes. Alternative (all six after Deletion 86 to 91) keeps every old row but splits the thematic groups; rejected.

The status block is 15 lines for an admin and 16 for the owner, each at most about 60 UTF-16 units (icon 2, name at most
20, `: `, state at most 36), so the Main text is about **1.1k units** (header 90, hint 120, owner line 70, 16 lines about
900) against the 3800 cap: the text budget is not what forces anything (check C18-4). Each new line reads `{icon}
{page}: {state}` through the existing `settings_main_state_line`.

## Text Styling (replaces Typography)

Phase 11 to 17 styling stands: `<b>` only on "Settings", the group title and the value inside a `…: <b>{value}</b>` line (the
Antiflood and Captcha precedent: `settings_warns_limit`, `settings_warns_action`, `settings_lang_current`,
`settings_log_status`), `<code>` on the chat ID, plain text for hints and notices, button labels plain text. **No new
markup.** Command names (`/setlog`, `/unsetlog`, `/lang`, `/report`) are plain text inside a translated string and are
not translated. A state icon is a code-side prefix (`{icon} {name}`), so a name is the same string in the cell, the
line and the title. The reused command strings keep their own markup (`<b>` and the `\n` line breaks of
`reports_status_*`, `admin_anon_admin_*`, `aispam_status_enabled`, `aispam_data_notice`) and are sent in HTML, where the
menu already sends them; the printf strings (`admin_anon_admin_*` take `%s`, `language_changed_group` takes `%s`,
`warns_limit_updated` takes `%d`) are filled with `fmt.Sprintf` after translation, user text first escaped, as the
commands do.

**No string of this phase carries a Staff Group, a member, a user, a log channel title or ID, or a count of members or
messages.** The group's own title appears only in the group line and in the reused `admin_anon_admin_*` text. Numbers:
`{n}` (the warn limit, "{n} on", "{n} locked") and the page numbers of `staff_panel_page`.

## Status Icons (replaces Color)

Phase 16 and 17's icons stand (`➖ 🗑 ⏳ 🚫 ❔ ✅ ❌ ⚠️ 💬`). This phase adds **six page icons** and **two state icons that only
the Locks page draws**. A `grep` of the settings code and of the `settings_` locale keys (2026-11-12) found none of them in use as a page or
section icon: pages `👥 🔒 🧩 🌊 🔑 🎉 👋 📜 🛂 🧹`, sections `🔔 🤖 💬`.

| Surface | Icon | Why |
|---------|------|-----|
| Warnings (Main, `Order` 42) | `🚩` | a flag raised on a member; `⚠️` is reserved for foot notices |
| Locks (Main, `Order` 44) | `🔐` | a closed lock with a key; close to Lockdown's `🔒` on purpose (both are locks) and different enough to tell apart in the grid (A18-A18) |
| Switches (Main, `Order` 86) | `🔘` | a radio button |
| Language (Main, `Order` 87) | `🌐` | a globe |
| Log channel (Main, `Order` 88) | `🧾` | a receipt, the log |
| Anonymous admins (Main, `Order` 89) | `🎭` | a mask (one code point; `🕵️` is two) |
| Locks page, a locked kind | `🔒` | the state icon of a cell and a line |
| Locks page, an unlocked kind | `🔓` | the state icon of a cell and a line (A18-A11; the shared `settingsStateIcon` `✅ ❌` would read "allowed" against "locked") |
| Switches, Log channel, Anonymous admins | `✅` `❌` | `settingsStateIcon` / `settingsStateWord`, as every switch of the menu |
| Status slot | `🚫` (cannot), `❔` (could not check) | Phase 16, reused unchanged on the Locks page and for the AI line |

State is never an icon alone: every cell of a grid is backed by a body line with the state word, and every full-width toggle
carries its word. A **stored value no choice carries** (a database edit; no menu path creates one): a warn action other
than ban, kick or mute is drawn as stored (escaped), an empty one as `Not set` (`settings_state_not_set`), nothing marked and
the inert line shown; a group language outside the enabled codes is drawn as its stored code (escaped) with nothing marked;
a warn limit above 100 is drawn as stored and the stepper's targets clamp to 100.

### 2. Choosing a value: absolute targets, strict allow-lists (D-03)

Every button sends the **absolute** target in `v`, so a double tap is harmless. Validation runs in step 1 (control `Validate`
and `Actions`, or the action's `Validate`), before any I/O, and a false answer is `common_callback_invalid_request`:

| Control | Press | `v` accepted in step 1 | Notes |
|---------|-------|------------------------|-------|
| Warnings `l` | `st` | `settingsParseNumber(v, 3)` (1 to 3 digits) | the apply function refuses 0 and over 100 with the command's own `warns_limit_range_error`; a step whose target equals the stored limit (at 1 or 100, labelled `·`) writes nothing and answers the toast `settings_min_value` (`{min}` 1) or `settings_max_value` (`{max}` 100), reused |
| Warnings `m` | `st` | 1 to 10 lower-case ASCII letters (the Antiflood shape) | the apply function accepts `ban`, `kick`, `mute` only; any other word of that shape is refused with the command's own `warns_mode_unknown` (the word escaped) as a notice and writes nothing |
| Switches `r`, `a`, `j`; Log `s a u m r o`; Anonymous admins `m`; every lock code | `tg` | exactly `0` or `1` | `v` is the target: `1` turns it on or locks, `0` off or unlocks |
| Language `l` | `st` | exactly two lower-case ASCII letters | the apply function refuses a code outside the command's list (`uk en es fr hi ru pt id`) with `language_invalid_selection` and writes nothing |
| `kg` | action | exactly one key `v`, 1 or 2 digits | clamped to 1..pages in `Run` |

`st` on a toggle, `tg` on a stepper or a choice, a control the page does not register, an extra key, a missing key, and `c` and
`u` together or neither are invalid in step 1, as everywhere.

### 6. The Locks pager (D-09, Pitfalls 28 and 29)

- **Page size 12**, 22 locks, **two pages** (12 and 10). The page of a lock is its table's `Page` column. Opening the page (`op&p=k`)
  draws page 1; `kg` carries the absolute page `v`; Prev is drawn only after page 1 and Next only before the last page, so there
  is no dead button and no `·`; a `v` past the end draws the last page and one before it draws page 1.
- **A toggle redraws the page its lock is on**, so no page field travels with it (the callback is `a=tg&p=k&t=<code>&v=<0|1>`, 46
  bytes private).
- **The button carries the table code and the absolute value, never the lock's name** (Pitfall 28); the names are locale keys of
  at most 18 code points, so `icon + space + name` is at most 20 in every language (Pitfall 29, check C18-2).
- The page shows, for each lock, the value `/locks` shows; a lock with no row reads **Unlocked**, as the enforcement does.
  (`/locks` lists only locks that have a row; the page lists all 22, which does not change what any lock does.)
- `url` (`Links`) and `previews` (`Link previews`) are two table rows because the commands accept two names; the page does not
  claim they differ (A18-A11).

### 7. The Language page redraws in the new language (PAGE-03, D-06)

1. The press runs the pipeline with `p.tr` built from the group's language before the write (`ctxTr`: the group's language for a
   menu opened in the group).
2. `applyGroupLanguage` writes through `lang.ChangeGroupLanguage` (a same-language press writes nothing).
3. **In a group menu**, on a successful write the press's translator is rebuilt from the new code (`i18n.MustNewTranslator(code)`)
   before the page is rendered, so the redraw, the notice, the Back and Close labels and the header are in the new language; the next press
   builds its translator from the stored language (`ctxTr`) and agrees.
4. **In a private menu** the translator stays the opener's own language (`ctxTr` of a private chat is the user's language) and the
   page shows the group's new language **by its own name** (`Group language: Español 🇪🇸`). The hint says your own language is
   set with `/lang` in private (A18-4).
5. The success notice is `✅ language_changed_group` with `{s}` the new language's `language_name` + flag, in the redrawn language
   (the command replies in the new language too). A same-language press and a refused code show no success notice.

### 8. The Staff Group, stale state and forged callbacks (D-11)

- **All six pages are drawn and work in a Staff Group** exactly as the existing pages (no `Hidden`, no gate beyond the pipeline's);
  none reads a Staff Group row, none names one (D-21, D-32): `TestSettingsStaffPrivacy` renders every new screen in a group menu
  and in a private menu of an admin who is not the creator, in 8 languages.
- **Forged callbacks** (all `common_callback_invalid_request` in step 1, before any `getChatMember`): `st` naming a toggle, `tg` naming `l`
  of Warnings or Language, a `v` outside the table above, `kg` with a second key or a non-number, `op` with an unknown `p`, `c` and
  `u` together or neither. A well-formed press of a lock code the page does not register is invalid too.
- **Stale screens.** A page drawn before another admin changed the setting shows the old state until the next press; every draw
  and every redraw reads fresh through the page's reader and the right line fresh. A press writes the **absolute value it carries**.
- **Nothing is read or written for a press that does not pass**; the owner gate (4b) re-judges every press, Close included.
- **Rolling deploy:** a replica on Phase 17 code has none of the six pages, controls or `kg`: a press of any new button there is
  `common_callback_invalid_request`, and Main there lacks the six cells; accepted, like the other rolling-deploy caveats.

C18-5 **Main.** The six new lines and cells appear in `Order`; Welcome|Goodbye and Rules|Requirements keep their pairs; every state line from
   the readers (including `❔` when a read fails, one failing reader leaving the other lines intact); Main makes **no Telegram call** and
   writes nothing; the Staff Group, Lockdown and every Phase 10 to 17 cell are byte-identical to before.
C18-6 **Reads create nothing.** Opening each page and Main leaves no `warns_settings`, `report_chat_settings`, `chats`, `admin`, `greetings`,
   `chat_lang`, `log_channel`, `locks` or `ai_spam_settings` row that was not there; a read error is the cannot-open edit (the unknown mark on
   Main), never a default shown as stored.
C18-7 **Parity (PAGE-10).** For each of the nine settings: the menu press and the command leave **the same stored row and the same cache**
   (`TestSettingsParityWarnLimit`, `…WarnMode`, `…Reports`, `…AISpam`, `…AutoApprove`, `…Language`, `…LogCategory`, `…AnonAdmin`, `…Lock`),
   on a chat with no row and on a chat with a row, writing a Go `false`, `0` and `""` where the value is one; a double tap is the same state;
   a failed write redraws the stored state with `⚠️ common_settings_save_failed` (or the command's own failure key) and the callback is
   answered once.
C18-8 **Drift.** Each page reads what its command and the module that enforces it read (`TestSettingsDrift{Warns,Reports,AISpam,AutoApprove,Language,LogChannel,AnonAdmin,Locks}`):
   a value written by the command is on the page at the next draw and the reverse, across the cache (a row written directly then
   `cache.ResetLocalForTest`).
C18-9 **Authority parity.** Per control, with the right of section 4: no write for an administrator the command refuses (bot not admin: the
   notice, nothing written; an administrator without `can_change_info` on Auto-approve; **a non-owner on Anonymous admins**); where the menu
   allows a control the command allows it too (`TestSettingsAuthorityParity{Warns,Switches,Language,LogChannel,AnonAdmin,Locks}`, with the
   documented carve-out); `TestSettingsGateAllDoors` is unchanged and still passes.
C18-10 **Warnings.** The stepper's targets clamp to 1..100 and a step at a bound is `·`, answers the toast and writes nothing; a first limit
   write on a chat with no row stores mode `mute`, a first action write stores limit 3 (so neither press changes the other value the page
   shows); a stored `tban`, `tmute` and `''` draw the inert line, nothing marked, and a press of Mute/Ban/Kick replaces it; a forged `v=tban`
   is refused with `warns_mode_unknown`; Main shows `Limit n, action`.
C18-11 **Switches and the AI status.** The six combinations of (AI available or not) x (stored On, Off): the data notice only when available;
   the `🚫` line only when not; the toggle hidden only when unavailable **and** Off; an On press while unavailable is the alert and writes
   nothing and redraws the Off-only form; Off always works; a stored On while unavailable shows the toggle and the line; the read of
   `config.AppConfig` makes no network call; Reports and Auto-approve are unaffected.
C18-12 **Language.** A press in a group menu redraws the whole screen, the notice and the Back and Close labels in the new language (assert the
   edit's text and keyboard against the new locale, `RealLocale`); in a private menu the screen stays in the opener's language and shows the
   group's new language by its name; `chat_lang`, `chat_settings` and `chat` are dropped; a same-language press writes nothing and shows no
   notice; a code outside the command's list is refused; the eight cells fit; a stored unknown code draws as stored with nothing marked.
C18-13 **Log channel.** A press with a channel linked flips exactly that category (the other five unchanged) through `applyLogCategory` and posts
   the same `#SETTINGS` entry as `/log` and `/nolog` (and none for a refused or failed press); with no channel it is refused with
   `logs_not_set` and writes nothing; **no screen, notice or alert contains the channel's title or ID** in either menu (the fake knows both);
   Main shows Linked / Not linked.
C18-14 **Anonymous admins.** The live creator with the bot an administrator changes the mode and the command then reads the same; a non-owner
   administrator is refused with `chat_status_owner_cmd_error` and nothing is written or edited; the creator with the bot not an administrator
   gets the notice `chat_status_bot_not_admin` and nothing is written; opening and viewing need only the admin check; a same-value press
   redraws and writes nothing; the group title in the reused text is escaped.
C18-15 **Locks.** The table covers **exactly** the keys of `lockMap` and `restrMap` (22), one row each, so a lock added to the commands without
   a row fails the test and the reverse; the table's page sizes are 12 and 10; every code's `NameKey` exists in 8 locales; page 1 opens, `kg` turns
   pages with Prev only after the first and Next only before the last; a toggle redraws the page its lock is on and the stored value is what
   `/locks` then shows; a lock with no row reads Unlocked; the press writes the absolute value through `locks.UpdateLock` and drops `locks_map`;
   a failed write shows `locks_lock_failed` / `locks_unlock_failed` with the lock's name; the right line (🚫 for a definite cannot, ❔ for
   unknown, nothing when the bot can delete) appears once per draw and never disables a button.
C18-16 **Staff Group and privacy.** In a Staff Group all six pages open and work; `TestSettingsStaffPrivacy` renders every new screen in 8
   languages, in a group menu and in a private menu of an administrator who is not the creator, under every outcome above, and fails on a Staff
   Group title or ID, a log channel title or ID, a member name or a count.
C18-17 **Locale tests.** `settingsLocaleLimits` gains 55 rows and still covers exactly the `settings_` keys (330 before, **385** after); each new
   key is present and non-empty in all 8 locales, within its ceiling, no markup beyond `<b>` where the English has it, placeholders equal to
   English; `make check-translations` passes. It cannot see keys read through a table field (`NameKey` of the lock table, the category table,
   the page `TitleKey`), which is why `settingsLocaleLimits` and a new `TestSettingsLocksKeysExist` (the lock names, the category names, the two
   state words, the six page names, in 8 locales) are the guard.
C18-18 **Cost.** Main 0 Telegram calls; each page but Locks the pipeline's calls only; Locks exactly one `getChatMember` of the bot per draw through the
   pacer, none for a refused press; no call with Redis down beyond the pacer's one-replica fallback.
C18-19 **Honesty.** With the real dispatcher: an exempt sender's locked message stays (an admin's, an approved member's), a non-exempt one is deleted
   when the bot can delete; a limit reached with each of Mute, Ban, Kick applies it and clears the warns; a stored `tban` applies nothing at the limit;
   `/aispam on` and the page's On refuse the same way with the AI unavailable; an anonymous admin's command needs the proof button with the mode Off and not
   with it On.
C18-20 **Characterization first.** One golden per extracted command (`/setwarnlimit`, `/setwarnmode`, `/reports on|off`, `/aispam on|off`, `/autoapprove on|off`,
   the language callback, `/log`, `/nolog`, `/anonadmin on|off`, `/lock`, `/unlock`) is recorded **before** its function is extracted and is never re-recorded; it
   asserts the requests and replies, including the replies of the failure paths.
