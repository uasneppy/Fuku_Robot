- UI-SPEC check 11 asks the five switch rows to "carry the ceiling 20 (never 26)". The generic `TestSettingsLocaleKeys` counts a template as written (`utf8.RuneCountInString` at line 312), where `{state}` is 7 characters, so a row of 20 would fail a correct 18-character translation. Resolution (research S-05, Open Question 12, orchestrator note): the rows are `{26, 26}` and the binding rule is the new rendered check, which replaces `{state}` with the one-code-point icon and fails above 20. The rendered limit always wins, as the UI-SPEC says.
- The four keys renamed by the UI-SPEC (`settings_btn_edit_*_toggle`, `settings_btn_edit_clean_*`) are renamed in plan 12-10, together with the code that stops drawing them as buttons; this plan leaves them and their existing 40-code-point check alone.
- Translations follow the UI-SPEC per-locale note: es `Medio bajo texto`, id `Media bawah teks`, fr `Suppr. dernier`, ru `Один раз` for Greet once; shorten a translation, never truncate in code. A native-speaker read is a live check in `12-SPIKE.md`.
