# Phase 16 - UI Design Contract

> Visual and interaction contract for the **Deletion** page of the settings menu: one Main cell and one Main state word,
> a hub screen, a Service messages list and a Bot messages list, one screen per row with the preset choices, the
> delete-right line (DEL-08) on every one of them, the Staff Group exclusion (D-18), every new callback with its
> worst-case size, every new string with its key and ceiling, and the checks that prove it.
> Generated by gsd-ui-researcher; to be verified by gsd-ui-checker.
> Upstream: 16-CONTEXT.md D-01..D-19 (locked, not reopened; the UI decisions are D-03, D-04, D-14..D-19), REQUIREMENTS
> DEL-01, DEL-02, DEL-07, DEL-08, MREQ-15, PLAT-05, ROADMAP Phase 16, the APPROVED Phase 15 and Phase 14 contracts
> (`15-UI-SPEC.md`, `15-UI-CHECK.md`, `14-UI-CHECK.md`, whose structure, section order, string-table style, worst-case
> callback table, row budget table and amendment style this file copies), AGENTS.md (Callbacks `settings|v1`, the Main
> page, the Member requirements page and rule-screen bullets, the message editor pages bullet, the private group list,
> Permissions with `settingsRightChangeInfo`, Subsystem traps for D-21 and D-32) and the code of
> `fuku/modules/settings_pages.go`, `settings_menu.go`, `settings_mreq.go`, `settings_card.go`, `settings_edit.go`,
> `settings_staff.go`, `fuku/i18n/settings_locale_test.go` and `locales/en.yml`.

This phase has no web screen. Everything is a Telegram message in HTML parse mode plus an inline keyboard, on the one
surface the settings menu always had: the menu message, private or opened in the group, edited in place. There is **no
group-side text** in this phase (the deletions themselves post nothing), so no `mreq_`-style group string exists.
Anything not restated here is unchanged and applies to the new page: the message anatomy, text styling, the press
pipeline (`settingsPress.verify`, owner gate at step 4b, one answer per press), the rights model, the "never name the
Staff Group" rule (D-21, D-32) and the Phase 11 to 15 limit tables.

The page is registered from its own file (`settings_deletion.go`) through `registerSettingsPage`. One framework field is
added to `settings_pages.go` (amendment M24); nothing else in that file changes. All rules are Keep or Off by default
(a missing row means Keep or Off, D-01) and nothing is preselected.

## Text Styling (replaces Typography)

Phase 11 to 15 styling stands: `<b>` only on "Settings" and the group title, `<code>` on the chat ID, plain text for
names, state words, status lines and hints, button labels plain text, escaped user text spliced after translation.
**No new markup.** Command names (`/cleanservice`, `/ban` and so on) are plain text inside a translated string and are
not translated. The delete-right line carries its icon as a **code-side prefix** (`🚫 ` or `❔ `), never inside the
locale template, so translators never touch it and test strings stay icon-free. The state icon of a line and of a cell is
also a code-side prefix (`{icon} {name}`), so a name is the same string in the cell, the line and the screen title.
**No string of this phase carries a group title, a member, a user, a chat ID, a count of messages or members, the Staff
Group or a number other than `{n}` (the Main and hub state) and `{n}` of the custom delay.**

## Status Icons (replaces Color)

Phase 9 to 15 icons stand (`✅` stored choice and "on" switches, `❌` off, `🚫` cannot work here, `❔` unknown, `⚠️`
refusal notices). This phase adds three **state icons**, drawn only before a row's name on the lists and the Currently
line, never alone (the state word is always written next to them):

| Icon | State | Used for |
|------|-------|----------|
| `➖` | Keep (a service type) or Off (a bot kind): no rule | list lines, list cells, Currently line |
| `🗑` | Delete now (delay 0) | the same three |
| `⏳` | After N: a stored delay of 1 to 86400 seconds | the same three |

Why not `settingsStateIcon` (`✅`/`❌`): `❌ Member joined: Keep` reads as "member joined is broken or removed" and `✅`
would not tell Delete now from After N. `➖` keeps the cross for "a switch is off" (Welcome, Goodbye, Requirements). The page
icon is `🧹` (Main cell and `Icon` of the page; unused by every other page: `👥 🔒 🧩 🌊 🔑 🎉 👋 📜 🛂`); the two hub
section icons are `🔔` (service notices) and `🤖` (the bot's own messages). The unknown mark `❔` stands for an unreadable
state in the Main status line only (a hub, list or row read that fails is the cannot-open edit). Flagged A16-A3.

### 2. Choosing a delay (D-04, D-16)

Presets are the only choices; there is no stepper, no typed number and no custom delay. Every button sends the **absolute**
target in `v`, so a double tap is harmless:

| `v` | Meaning | Label key | Service | Bot |
|-----|---------|-----------|---------|-----|
| `n` | no rule: Keep (service) or Off (bot) | `settings_del_state_keep` / `settings_state_off_plain` | yes | yes |
| `0` | delete now (a service rule only) | `settings_del_state_now` | yes | **no** |
| `10` | 10 seconds | `settings_del_delay_10s` | yes | **no** |
| `60` | 1 minute | `settings_del_delay_1m` | yes | yes |
| `600` | 10 minutes | `settings_del_delay_10m` | yes | yes |
| `3600` | 1 hour | `settings_del_delay_1h` | yes | yes |
| `21600` | 6 hours | `settings_del_delay_6h` | yes | yes |
| `86400` | 24 hours (the cap, D-04) | `settings_del_delay_24h` | yes | yes |

The six delay labels are used for **both** the choice buttons and the `{delay}` of `After {delay}`; a bot kind offers the
subset (D-04: 1, 10, 60 minutes, 6 h, 24 h), the one labelled "60 minutes" in the decisions is `1 h`.

Validation, all in step 1 before any I/O, `common_callback_invalid_request`: the control's `Validate` accepts exactly the
row's own presets, written canonically: `v` is `n`, or the decimal seconds in the row's preset list with no sign, space,
non-ASCII digit or leading zero (`0` is the one zero). `v=5`, `v=05`, `v=86401`, `v=-1` are invalid; `v=0` and `v=10` on a
bot row are invalid; `tg` naming a row code is invalid. Why not "any value up to 86400" (D-04 says `v` is at most 5
digits): a strict allow-list makes a forged number impossible to store and costs nothing, because the page offers
presets only; Phase 17's rows bring their own preset lists through the table (A16-A5).

**What a press does.** The row's apply function (one beside `/cleanservice` for joined and left, D-02) validates, writes
(Keep or Off removes the row; a delay upserts it; joined and left go through the flag as D-02 says, in one transaction),
calls `cache.DeleteCache` for every key it affects, and returns the **effective state read back**. A press of the state
already stored writes nothing (judged on the cached loader, whose key is in `skipLocal`, so another replica is not behind)
and redraws. A failed write redraws the row screen from the stored state with `⚠️ common_settings_save_failed`; a read-back
that failed reloads through the cached loader, and when that fails too it is the cannot-open edit.

**Drawing a stored state.** The word and icon come from the stored value by one function: no rule is `➖` and the Keep or
Off word, 0 is `🗑 Delete now`, a preset is `⏳ After {delay}` with the preset's label, and any other value 1 to 86400 (only
possible from outside the menu: a database edit, or a Phase 17 row) is `⏳ After {delay}` with `{delay}` =
`settings_del_delay_custom` (`{n} s`, the seconds) and **no choice button is marked** `✅`. A 0 stored for a bot kind
reads `🗑 Delete now` and marks nothing. For joined and left the state is the **effective** one of D-02 (Keep while the
flag is off, whatever a stale row says).

### 3. Effects of `/cleanservice` on the screens (D-02)

Joined and left share storage with `/cleanservice`: a `/cleanservice on` in the group makes both rows read Delete now at
the next draw, `off` makes both read Keep, and a press on either row on this page writes the same state the command would
(a parity test, check 15). Both rows show `settings_del_hint_cleanservice` (the Service list and the two row screens): one

### 4. The delete-right line (D-17, DEL-08)

One status, three outcomes, on **every** deletion screen (hub, both lists, every row screen), in the slot shown in
"Message Layout". Never an error text, a refusal or the cannot-open edit.

| Outcome | Line | Shown when |
|---------|------|------------|
| bot can delete | none | the bot is the creator, or an administrator with `can_delete_messages` |
| bot cannot delete | `🚫 ` + `settings_del_no_right` | a definite answer: an administrator without the right, a member, restricted, left or kicked, or a Telegram 400 or 403 for the bot's own record |
| cannot be read | `❔ ` + `settings_del_right_unknown` | a 429, a 5xx, a transport error, a timeout, a shed pacer, a null or unreadable answer |

- **One live `getChatMember` of the bot per draw**, through the deletion pacer (`deletionPaced`, keys
  `fuku:delete:pace:*`, D-09) under `settingsDelHereTimeout` (3 s, a variable), never the admin cache and never
  `CanBotDelete`'s cached answer. It runs **after** the press is answered empty (the settings pattern: the read can take a
  moment and must not hold the spinner) and before the edit, so a redraw after a write also reads once. Main makes no call.
- **A rule can still be set while the bot cannot delete** (D-17): the line never disables a button and no press is
  refused for it. The rule is stored and the worker's own check decides at the time (D-07).
- **The status is a Telegram fact, not a configuration fact**, so it never says a setting, variable, key or right other
  than the one Telegram's own name for it (the quoted “Delete messages”, A16-A6).
- A Redis outage makes the pacer fall back to one replica's interval (D-09); it is never a line.
- Nuance, flagged A16-A6: a bot that is a plain member can still delete **its own** messages in a group, so on the Bot
  messages screens "I can't delete messages here" is conservative. D-17 fixes one rule for every screen; the line says
  "some of these settings may not work" rather than "nothing is deleted" so it stays true for the bot kinds in the edge case (checker F2).

### 5. Rights, the Staff Group and stale state (D-17, D-18)

| Press | Right | Refusal |
|-------|-------|---------|
| open the page, `dl`, `dr`, Back, Close | `settingsRightAdmin` (the live admin check every press already makes, plus the owner gate at step 4b) | the pipeline's own |
| a choice on a row (`st`) | `settingsRightChangeInfo`: the creator, or an administrator with `can_change_info` from the same member record, no extra call | alert `settings_no_change_info`, nothing edited or written (the right `/cleanservice`, `/cleanwelcome` and `/cleangoodbye` ask for through `CanUserChangeInfo`, so the menu refuses what the commands refuse) |

- **Staff Group.** The page is not drawn in a Staff Group (M24). Every other entry is a defence in depth against a forged
  button: a press of `dl`, `dr` or a control, in a group that is a Staff Group by a fresh `staff.GetStaffGroupFresh`, is
  answered `common_callback_invalid_request` as the press's one answer, edits nothing and writes nothing; a failed read of
  that row is the cannot-open edit and writes nothing (fail closed). The check runs after the pipeline and **before** the
  write. No refusal text says the group is a Staff Group (D-21).
- **Forged callbacks.** `dl` with an unknown `t`, `dr` with an unknown or section-only `t`, a control with a `v` outside its
  presets, a `tg` on a control, an extra key, a missing `t` or `v`: `common_callback_invalid_request` in step 1, before
  any `getChatMember`. A row code of a section that Phase 17 later adds is unknown on a replica that lacks it (rolling-deploy
  caveat).
- **Stale screens.** A menu drawn before another admin changed a rule shows the old state until the next press; every draw
  reads the rule fresh through the cached loader (key in `skipLocal`) and the right line fresh, so the next press shows the
  truth. A press of a button for a rule that is already in that state writes nothing.
- **Nothing is read or written for a press that does not pass.** The owner gate (4b) re-judges every press, Close included.

### 7. Hub growth (D-15, Phase 17)

The hub is a table of sections, each `{Code, Icon, NameKey, ListIntroKey, Rows func}`; the hub's lines and grid, the `dl`

### 8. No confirmation card (decided here, M28)

D-16 says presets send absolute values and a double tap is harmless; deleting messages sooner changes no member, no
punishment and nothing that cannot be set back with one tap. The worst result of a wrong tap is that a service notice or
the bot's own message disappears earlier than the owner wanted, a message that exists to be transient. Phase 13's card
exists because Kick, Ban and Mute act on people; nothing here does. So no choice draws a card, `settingsCardRows` is not
called, no `e` field exists on this page, and no callback of the page expires. The one thing a tap cannot undo is a
message already deleted, which the hint on Auto punishments and the Rules description already make clear. Flagged A16-A4.

## Accessibility and phone-width notes

- State is never icon alone: every list line and the Currently line carry the state word, and the choice buttons are
  words; the icon only helps scanning.
- `🚫` and `❔` are shapes distinct from the three state icons; `⚠️` stays reserved for refusal notices at the foot.
- The choice row of three (`10 s`, `1 min`, `10 min`) is the widest row of the page, at most 15 code points per cell; the
  Phase 13 Kick, Ban, Mute row is the same shape, so the pattern is known to fit a phone.
- The Service list's twelve cells are two per row like the Requirements grid (cells at most 20 code points). hi, ru and uk
  cells are checked on a phone (A16-A9); if a cell wraps, the key is shortened in place, no key added.
- The hub, the Service list and every row screen are readable without the keyboard: the body lists every state.
- A group menu's text is readable by every member of the group, and shows which kinds of messages are deleted: this is
  settings content like the other pages' (no member, user or count appears).
- No screen of this page uses colour, a link or a URL button; every action is a labelled button.

1. **Row budget.** Build each screen (Main with the page, hub, Service list, Bot list, a service row screen, a bot row screen) in a

   bot names rendered with each of `➖ 🗑 ⏳` at most 20; the choice labels (`Keep`, `Off`, `Delete now`, the six delays) with `✅ ` at
   most 13 EN / 15 other.
3. **Callback bytes and validation.** Every button at the worst-case IDs is at most 64 bytes (largest **50**, measured equal to the
   table); `Omitted` is 0 on every screen. Invalid before any I/O, with no `getChatMember`: `dl` with `t=x`, a missing `t` or an
   extra key; `dr` with `t=s` (a section code), `t=xx` or a missing `t`; `st&p=d` with `t=bw&v=0`, `t=bw&v=10`, `v=5`, `v=05`, `v=86401`, `v=-1`, `v=` or an
   unknown `t`; `tg` naming a row; `dr` with both `c` and `u`.
4. **Page fit.** In all 8 languages with a 64-rune multibyte group title: the hub, both lists with every right-line outcome and a
   notice, every row screen (17, with the longest row hint and a notice) and Main are at most 3800 UTF-16 units. Projected worst case at
   the ceilings is about 1.6k for the Service list (header 90 + group line 90 + intro 176 + 12 lines at 60 + right line 190 +
   two hints 226 + a notice 100), a row screen about 1.0k, so the margin is above 2k; the test is binding.
5. **The delete-right line.** With a fake bot that answers `getChatMember` for the bot: the creator or an administrator with
   `can_delete_messages` draws no line on the hub, either list and every row screen; an administrator without it, a member, a
   restricted bot, left, kicked and a 400 or 403 draw the 🚫 line exactly once; a 429, a 5xx, a transport error, a timeout, a shed pacer and
   a null body draw the ❔ line exactly once and **never** an error text, a refusal or the cannot-open edit; the line is in the
   status slot (after the description and hint on a row screen, after the state lines on a hub and list), the press is answered
   exactly once before the call, no screen is ever disabled by it, and a rule can be set with the line showing.
6. **Cost.** Count the fake bot's Telegram calls and Redis commands per draw: Main 0; hub, list and row screen exactly one `getChatMember`
   of the bot through the pacer (the pipeline's own calls unchanged); a choice press the pipeline's calls plus one for the redraw; the
   page makes no call with Redis down and the right line is identical with Redis down.
7. **States and words.** Every row, for stored none, 0, each preset, an unlisted delay (37 s) and a 0 on a bot row: the line,
   the Currently line, the cell icon and the `✅` mark are as section 2 says; joined and left read the **effective** state (flag off
   with a stale row is Keep; flag on with no row is Delete now; flag on with a row is that delay).
8. **Writes.** Each choice stores through the row's apply function: Keep or Off removes the row (a Go 0 is never confused with "no
   rule"), `v=0` stores a 0 for a service row, a delay upserts, the cache key is dropped (`delete_rules:<chat>`, and the
   greetings key for joined and left), the row is read back, a press of the stored state writes nothing, a double tap is the same
   state, a failed write redraws with `⚠️ common_settings_save_failed` and the old state, and the callback is answered exactly once.
9. **Rights.** Opening needs only the admin check; every `st` needs `settingsRightChangeInfo` judged on a fresh member record (an
   administrator without `can_change_info` gets the alert `settings_no_change_info` and nothing is edited or written; the creator and an administrator with
   it pass), the same decision as `/cleanservice`, `/cleanwelcome` and `/cleangoodbye` (`TestSettingsAuthorityDeletion`, with the
   documented stricter-than-commands carve-out of the owner gate).
10. **Staff Group.** In a Staff Group: Main has no Deletion cell and no line and `MainState` is not called; `a=op&p=d`, `dl`, `dr` and
    every control are answered `common_callback_invalid_request`, edit nothing, write nothing and make no `getChatMember` of the
    bot; a failed Staff Group read is the cannot-open edit with no write; in a group that is not a Staff Group, linked or not, the page is drawn. No
    text of any screen or alert contains a Staff Group title or ID.
11. **Main and hub state.** `Off` with no rule on, `{n} on` with n the number of rules that are not Keep or Off (joined and left by their effective state),
    the unknown mark when a read failed; the hub lines carry each section's own n; Main makes no Telegram call.
12. **Navigation.** Back from a row screen is `a=dl&t=<its section>`, from a list `a=op&p=d`, from the hub core `bk`; Close deletes
    the menu or edits it to `settings_closed`; no screen has a Refresh other than the Main cell's `a=op&p=d`.
13. **No card, no expiry.** No screen of the page has an `e` field, a Yes or a No; `settingsActCancel` is never produced.
14. **Locale tests.** `settingsLocaleLimits` gains 57 rows and still covers exactly the `settings_` keys (255 before, **312** after);

15. **Parity and drift.** Joined and left: the menu press and `/cleanservice` leave the same stored flag, row and cache state
    (`TestSettingsParityCleanService`); every row: the page reads what the watcher and the send sites read (`TestSettingsDriftDeletion`,
    through the cached loader and `greetings.LoadSettingsContext`); opening writes nothing and creates no greetings or rules row.
16. **Privacy and stale state.** `TestSettingsStaffPrivacy` as above; a row screen drawn before a rule changed on another replica shows the

    still stores the rule.
