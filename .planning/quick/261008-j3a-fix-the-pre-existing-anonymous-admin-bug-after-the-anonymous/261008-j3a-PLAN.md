<objective>
Fix the pre-existing anonymous-admin re-entry bug so that, after the "prove you're admin" tap, the re-entered command finds its chat. Today `/ban` (and every other anonymous-capable command behind `helpers.RequireGroup`) silently does nothing after the tap.

Root cause (reproduced during planning with a real-dispatcher probe: after the creator's tap there were zero banChatMember calls and zero new replies): `verifyAnonymousAdmin` (`alita/modules/bot_updates.go:190-195`) restores `EffectiveMessage` and the sender but clears the callback query on the shared update. That leaves `ctx.Update` with neither a callback query nor a message, so `chat_status.extractChatFromContext` (`alita/utils/chat_status/chat_status.go:97`) returns nil. `RequireGroup` then returns false, and `PermissionResponder.Respond` drops its reply. `anonPipelineHandler` (`alita/modules/moderation.go:349`) therefore stops at the first check, with no reply.

Fix the shared path: rebuild the context as the message update the admin would have sent. That means a fresh `gotgbot.Update` whose `Message` is the cached command, with `EffectiveChat` pointing at that command's chat. Every chat-derived value after the proof (checks, refusal replies, the action itself) then comes from one chat: the chat the tapper was just verified admin in. Add a fail-closed check that the callback's `c`, the proof button's chat and the cached command's chat are the same chat.

A prototype of exactly this change was run against a scratch copy during planning. The probe banned the target and posted the ban reply after the tap, and `go test -tags testtools ./alita/modules ./alita/utils/chat_status ./alita/utils/helpers` all passed, including TestLockdownAnonymousAdminProof and TestUnapproveAllCallbackCancelInvalidAndUnavailableMessage.

Purpose: Core value says "the bot never lets anyone act in a group where they aren't an admin". This fix restores anonymous-admin moderation and keeps every per-group check: none is skipped, and each runs against the right chat for the real tapper.
Output: the fixed `verifyAnonymousAdmin`, a new real-fixture end-to-end test file, extended unit tests, and the updated AGENTS.md rule. The deferred item is marked resolved.
</objective>
