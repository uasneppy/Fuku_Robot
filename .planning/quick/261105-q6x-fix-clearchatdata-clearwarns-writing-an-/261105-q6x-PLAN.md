# Quick task 261105-q6x: a reset must store a valid warn mode on PostgreSQL

## Problem

`ClearChatData` resets a chat's warn settings in `clearWarns` (`fuku/db/backup/backup.go`) by inserting
`models.WarnSettings{WarnLimit: 3}` with an empty `warn_mode`. The legacy CHECK `chk_warns_mode` (migration
20250805204145, still active) allows only `NULL` or `ban`/`kick`/`mute`/`tban`/`tmute`, so on PostgreSQL the insert
fails with SQLSTATE 23514 and the whole all-modules reset rolls back. SQLite builds its check from the model tag
(`chk_warn_mode`, which allows `''`), so `make test` cannot see it.

## Tasks

1. **Reproduce** on a throwaway PostgreSQL 16 cluster (data directory under `/var/lib/postgresql`, trust auth, no
   secret in any file, removed afterwards): apply the repository migration chain, run
   `TestClearChatData_AllModules` and `TestClearModuleData_IndividualModules` with `FUKU_TEST_DATABASE=true`.
2. **Red test first**: `TestClearWarnsRestoresFreshChatDefaults` (reset stores what a fresh chat gets, warns are
   gone, the cache is not stale). It must fail on PostgreSQL (23514) and on SQLite (empty mode) before the fix.
3. **Fix** `clearWarns` to store the warns repository's default mode (`mute`; the model and migration define none).
   Keep the limit, the error handling and the returned cache keys. Update the old assertion that a reset leaves the
   mode empty.
4. **CI proof**: add `TestClearChatData_AllModules` and the new test to the `test-postgres-integrity` `-run` list
   (keep the `$$` anchor), then run `make test-postgres-integrity` against the throwaway cluster with the CI env.
5. **Rules**: AGENTS.md documents the two live `warn_mode` checks and the guarantee (same commit); `gofmt`,
   `go vet -tags testtools ./fuku/db/backup`, `make check-docs`, `make check-translations`.

## Out of scope

- `importWarns` (a backup whose `warn_settings` has no `warn_mode` fails the same way); what an import should do
  with a missing mode is a product decision.
- `TestGreetedMembersStayOutOfBackup` does not exist on this branch (see SUMMARY).
