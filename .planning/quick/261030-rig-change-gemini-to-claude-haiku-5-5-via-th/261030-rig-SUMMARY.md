# Quick 261030-rig: Gemini to Claude (Anthropic Messages API) for the raid AI image check

**Raid AI image checks now call Claude (`claude-haiku-5-5`) through the Anthropic Messages API with a forced strict tool call; the Gemini client, its spike tool and every mention of the old provider outside planning history are gone.**

## BREAKING CHANGE (for the PR notes, OD-7)

The old image-check key and model environment variables are no longer read (not aliased). To keep raid image checks a deployment must set `ANTHROPIC_API_KEY` (optionally `ANTHROPIC_MODEL`, default `claude-haiku-5-5`). Without it the image checks are off, no image leaves the server, and the text checks (TypeSafe) are unchanged. The Task 1 commit carries the `!` header.

Because the bot reads the standard `ANTHROPIC_API_KEY` name, a key exported for another tool on the same host turns the image checks on (documented in AGENTS.md, environment.md and sample.env).

## Unverified API-shape assumptions

All taken from the plan's cached claude-api skill notes (2026-10); nothing was checked against the live API:

- Request: `POST /v1/messages` with `x-api-key`, `anthropic-version: 2026-10-21`; image block before the text block; strict tool with `additionalProperties: false`; `tool_choice` `{"type":"tool","name":...,"disable_parallel_tool_use":true}` accepted on Haiku 5.5; `thinking` `{"type":"disabled"}` accepted at default effort; no sampling field accepted.
- Response: forced call ends with `stop_reason: "tool_use"`; refusal is HTTP 200 with `stop_reason: "refusal"` and `stop_details.category`; error envelope and `retry-after` seconds on 429; 529 `overloaded_error`.
- Spike-only: `thinking` `{"type":"adaptive"}`, `output_config.effort`, `tool_choice` `{"type":"auto"}` and `GET /v1/models/{id}` returning `id`, `display_name`, `max_input_tokens`, `max_tokens`; that `xhigh`/`max` effort with thinking disabled answers 400 (the tool refuses that combination up front); the default prices 0.10 / 0.50 dollars per million tokens are the plan's list prices for prompts up to 100K tokens at the time of writing.
- The probe assumes the API checks the key before reading the body, so a fake key answers 401 for every variant and tells nothing about the request shape; therefore `-probe -fake-key` only proves reachability and only a real key tests the shape. If the API validates the body first, a 400 `invalid_request_error` is reported as "field rejected" (that path is tested), so the tool is correct either way.
- `claude-haiku-5-5` as the default model id and `2026-10-21` as the API version are taken as given.
