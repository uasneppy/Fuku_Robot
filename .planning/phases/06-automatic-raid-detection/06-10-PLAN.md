## Phase Goal

**As a** group admin, **I want to** have raids detected and locked down automatically, **so that** my group is protected when no admin is online.

**This slice:** the owner's stats, the database carry-over and the docs all tell the same story as the bot.

## Decisions taken here (Claude's discretion, recorded)

- Stats lines: "<b>Raid detection:</b>" with "Custom settings: N chats", "Join surge off: N chats" and "Flood off: N chats" (chats without a row use the defaults, so they are not counted).
- The carry-over test lives in package migrations, so it reuses the runner's own `cleanSupabaseSQL` and `splitSQLStatements` and executes the file exactly as the runner would. It runs only with `ALITA_TEST_DATABASE=true` and `DATABASE_URL` (the CI PostgreSQL integrity step, after the migration chain), opens its own connection, does everything in one transaction it rolls back, and is skipped elsewhere. Plan 06-11 adds it to the Makefile list.
- Docs: pages marked `<!-- MANUALLY MAINTAINED: do not regenerate -->` keep the marker and are edited by hand; the architecture pages are hand-written and not generated. No generated page changes here (the help texts change in plans 06-09 and 06-11).
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet` and `gofmt -l` stand in for `make lint`. No PostgreSQL server is available, and executors must never start one by any means; TestRaidDetectionCarryOver is only compiled and seen to skip here, and runs in CI.
