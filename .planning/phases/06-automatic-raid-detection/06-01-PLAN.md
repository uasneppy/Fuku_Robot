<objective>
Prepare the lockdown core for automatic triggers without changing anything an admin sees today. The start sequence of /lockdown (bot rights, the raw permissions snapshot, the insert behind the one-active-lockdown index, the lock call, the confirmation, the worker wake) moves into `startLockdownRow`, which /lockdown calls with every reply unchanged and which the join-surge and flood triggers will call too. A lockdown row records its trigger kind and numbers, and the alert renders a trigger line for the two automatic kinds.

Task 1 is the shared start path with its outcomes and the trigger columns. Task 2 is the alert's trigger line.

Purpose: D-13 (an automatic lockdown is exactly a /lockdown), D-21 (trigger numbers as columns, rendered per language), LOCK-10 (one start path, one winner), ROADMAP Phase 6 criterion 1 (the alert names the join surge and its count).
Output: migration 20261018120000, the trigger constants and columns, lockdown_start.go, the refactored /lockdown, the alert trigger line, two locale keys, AGENTS.md rules.
</objective>

## Phase Goal

**As a** group admin, **I want to** have raids detected and locked down automatically, **so that** my group is protected when no admin is online.

**This slice:** the lockdown a trigger will start is the very same lockdown /lockdown starts, and its alert can say what triggered it.

## Decisions taken here (Claude's discretion, recorded)

- The phase has two migrations, each written once: this plan's adds the trigger columns to `chat_lockdowns` and the `(chat_id, lift_started_at)` index the D-15 quiet period reads (plan 06-06); plan 06-02's creates `chat_raid_detection` with the carry-over. The model's new columns must exist in PostgreSQL before any row is written with them, so they ship with the code that writes them.
- `trigger_kind` gains `join_surge` and `flood` (the column has no CHECK, D-13); `trigger_window` is in seconds; the three columns are 0 for a manual lockdown. The numbers are columns, never part of `reason`, so every destination renders its own language (D-21).
- The extraction is behaviour-preserving (research Pattern 6): `/lockdown` keeps its supergroup reply, its `GetActiveFresh` plus settle pre-step and its success text, and maps each outcome to exactly the reply it sends today. The existing lockdown suites are the safety net and must pass unchanged.
- The alert's trigger lines are rendered here for both automatic kinds (one renderer); no trigger exists yet, so the tests write such rows directly.
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet -tags testtools` and `gofmt -l` stand in for `make lint`. No PostgreSQL server is available, and executors must never start one by any means; the migration is proven on PostgreSQL by CI's migration chain.
