<objective>
Admins control both triggers. `/autolockdown` shows them; `/autolockdown joins|flood N|on|off` changes one, after a live check that the sender is the owner or an administrator who can restrict members. Settings are written with one column-targeted upsert per trigger and invalidated in the shared cache, and the key is kept out of the 10-second in-process layer, so the next join or message on any replica follows the new value.

Task 1 is the end-to-end path: an admin changes a threshold and the next burst follows it. Task 2 pins authority, the grammar, the basic-group answer and the repository's edges.

Purpose: ROADMAP Phase 6 criterion 3, RAID-06, D-09 to D-12, D-18, D-21.
Output: autolockdown.go, the repository writes, the skipLocal entry, locale keys, AGENTS.md rules.
</objective>

## Phase Goal

**As a** group admin, **I want to** have raids detected and locked down automatically, **so that** my group is protected when no admin is online.

**This slice:** an admin can turn each trigger off or tune it, and the next burst follows the new setting.

## Decisions taken here (Claude's discretion, recorded)

- One command, two authorities (research Pattern 8): `requireAutoLockdownAuthority` uses `requireLockdownAuthority(false)` when there are no arguments (any live creator or administrator may view) and `requireLockdownAuthority(true)` otherwise. The command is not Disableable, like `/lockdown`.
- Grammar: exactly two words after the command, `joins` or `flood` (case-insensitive), then `on`, `off` or a whole number. A number sets the threshold and turns the trigger on (D-21); `on` and `off` keep the stored threshold. Anything else gets the usage text, a number outside 3..500 the range text (D-18). The windows stay fixed (CONTEXT defers configurable windows).
- Repository writes are four functions, one per column set (`SetJoinEnabled`, `SetJoinThreshold`, `SetFloodEnabled`, `SetFloodThreshold`), each one `INSERT ... ON CONFLICT (chat_id) DO UPDATE` of only its own columns plus updated_at (the insert carries Go defaults for the rest), so two admins changing the two triggers at once never clobber each other and a Go false is always written (research Pattern 7). The cache key is deleted after a successful write; a failed write returns its error and the reply says nothing changed.
- `autolockdownApply(b, ctx, args)` holds the whole command body so plan 06-10's `/autoantiraid` alias can reuse it with `joins` prepended.
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet -tags testtools` and `gofmt -l` stand in for `make lint`. No PostgreSQL server is available; never start one (TestRaidDetectionSettings joins the PostgreSQL integrity list in plan 06-13).
