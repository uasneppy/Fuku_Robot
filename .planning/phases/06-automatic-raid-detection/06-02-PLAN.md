## Phase Goal

**As a** group admin, **I want to** have raids detected and locked down automatically, **so that** my group is protected when no admin is online.

**This slice:** only real joins count, each once, whichever way Telegram delivers them.

## Decisions taken here (Claude's discretion, recorded)

- The guard's input building moves into two small builders (`lockdownMemberJoinInput`, `lockdownMessageJoinInputs`) used by both the guard and the counter, so their performer rule cannot drift (research Pattern 3).
- The counter looks the performer up live only when `raidNeedsPerformerLookup` says so and hands its answer to the guard, succeeded or failed (plan 06-01 did this for the chat_member path; this plan does the same for service messages), so a join or a join message costs at most one live lookup and a failed one is never exempt, exactly as the guard's own lookup behaves today.
- A service message's counted members go to Redis in one script call; the fire check uses the count that call returns.
- The Redis-missing log line is the one from plan 06-01 (`raidNoRedisLogged`); tests reset it.
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet -tags testtools` and `gofmt -l` stand in for `make lint`. No PostgreSQL server is available; never start one.
