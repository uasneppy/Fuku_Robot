1. Migration `migrations/20261004120000_add_staff_groups_and_links.sql` (the timestamp is greater than 20261001120000). Start with a comment header like the ai_spam precedent. Use no top-level transaction statements, no CONCURRENTLY and no foreign keys.
   - Table `staff_groups`: `id BIGSERIAL PRIMARY KEY`, `chat_id BIGINT NOT NULL`, `owner_user_id BIGINT NOT NULL`, `title TEXT NOT NULL DEFAULT ''`, `created_at` and `updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()`, plus `UNIQUE(chat_id)`. Add index `idx_staff_groups_owner_user_id` on `owner_user_id` that is NOT unique (D-09: one owner can have several Staff Groups).
   - Table `staff_group_links`: `id BIGSERIAL PRIMARY KEY`, `group_chat_id BIGINT NOT NULL`, `staff_chat_id BIGINT NOT NULL`, `owner_user_id BIGINT NOT NULL` (the link maker, D-12), `group_title TEXT NOT NULL DEFAULT ''`, `health VARCHAR(24) NOT NULL DEFAULT 'ok'`, and the two timestamps.
   - Constraints on `staff_group_links`: `UNIQUE(group_chat_id)`, `CONSTRAINT chk_staff_link_distinct CHECK (group_chat_id <> staff_chat_id)`, and `CONSTRAINT chk_staff_link_health CHECK (health IN ('ok','bot_missing','bot_not_admin','bot_cannot_restrict'))`. Add index `idx_staff_group_links_staff_chat_id` on `staff_chat_id`.
   - The column is VARCHAR(24), not 16: 'bot_cannot_restrict' is 19 characters long.
