<objective>
An admin of the locked group cleans up the raid with one button. "Ban N recent joiners" on the alert opens a confirm card with N; Confirm starts a DB-driven ban run that the worker executes through the per-account core of plan 05-08, and the card reports banned, skipped and failed when the run ends. Approved users are read fresh and a failed read bans nobody.

Task 1 is the end-to-end path: button, card, run, bans, result. Task 2 makes N and the exclusions exact and the run safe when approvals cannot be read.

Purpose: ROADMAP Phase 5 success criterion 3, LOCK-12, LOCK-11 (the button on the alert), D-09, D-10, D-11, D-21, D-22.
Output: the approvals fresh read, the Ban button and card, the worker's run step, the result, a test file, locale keys, AGENTS.md rules.
</objective>

## Phase Goal

**As a** group admin or staff member, **I want to** get a lockdown alert with one-tap fixes, **so that** we can see a raid and clean it up fast.

**This slice:** one press, one confirmation, and the raid's accounts are banned for good.

## Decisions taken here (Claude's discretion, recorded)

- Approved users are read through a new uncached `approvals.ListApprovedIDsFresh` that returns its error, because the cached `IsUserApproved` turns a failed read into "not approved", which would ban. The module reads it through a seam variable (`lockdownApprovedLookup`) so tests can make it fail.
- Confirm calls `StartBanRun` with the approved users and the bot excluded (plan 05-08 also marks joiners an admin let in skipped `let_in`), stores the card's chat and message on the run, edits the card to "Banning N…" and wakes the worker. The worker step claims queued accounts in batches and hands each to `lockdownResponseBanOne`; the replica whose `FinishBanRun` wins edits the card with the result.
- The button label carries N when it is above 0 and readable, else a generic "Ban recent joiners". The confirm card states exactly what the call does: the accounts are banned for good (no end date) and cannot rejoin, the bot cannot undo it, and admins, approved users and people an admin let in are left out. It says nothing about the accounts' messages, because the call sends no `revoke_messages`.
- While the lockdown is no longer active the run is left untouched here; plan 05-11 stops and reports it.
