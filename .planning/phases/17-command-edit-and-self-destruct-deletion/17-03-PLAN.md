## Phase Goal

**As a** group owner, **I want** members' commands, late edits and, when I choose, every message removed automatically, **so that** the group stays clean and an edited message cannot slip spam in later.

After this plan the first rule works end to end in production wiring: with "Delete commands" on, a command the bot handles is answered and then disappears; the answer stays.

<objective>
Build the thinnest real slice of command deletion first (research S-01): the Processor wrapper, the registered-name predicate and the post-step that calls `deletionAct`, wired in `main.go`, proved through the real dispatcher with a real `WrapCommand` command and a real answer; then widen to raw commands, the cases that must keep a message, the library-matcher differential test and the polling context (D-01, D-02, D-03, D-21, D-22, D-23).

Purpose: the tracer proves the riskiest seam (after-the-answer, outside tracing, post-run state) on one commit before edits and self-destruct build on the deletion core.
Output: one production file, `main.go`, a test toolkit file, a test file, one main test, AGENTS.md.
</objective>
