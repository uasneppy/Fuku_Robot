<objective>
The image half of RAID-04. A new member's photo, GIF, sticker or video is a candidate on its own (D-01); the group-2 watcher hands it to the raid AI pool, a worker fetches the one frame D-12 names through `getFile` with a download that can never leak the bot token, and plan 07-02's client asks Gemini for a verdict. ## Phase Goal

**As a** group admin, **I want to** have AI flag borderline spam text and images, **so that** subtler raids still trigger a lockdown.

**This slice:** a wave of spam pictures or stickers from fresh accounts is recognised by Gemini and can lock the group, and the owner's key and the bot token stay secret.

## Decisions taken here (Claude's discretion, recorded)

- Media selection (`raidAIMediaRef`, research Pattern 8): `Photo` takes the size whose larger side is nearest 1024 px; a `Sticker` of type regular that is neither animated nor video is sent as is (WebP); an animated (TGS) or video (WEBM) sticker, an `Animation` (checked before the `Document` Telegram also sets) and a `Video` take their `Thumbnail`; a custom_emoji or mask sticker, a missing thumbnail, a video note, a document, a voice note and any `FileSize` over `gemini.MaxImageBytes` (5 MiB) give no candidate. The item key is `raidAIItemKey` (an album is `g:<media_group_id>`; plan 07-09 adds the album gate).
- Captions are not sent anywhere by the raid path; `/aispam` keeps judging them as before (D-03).
- Download (`raidAIDownload`): `GetFileWithContext` (gotgbot sanitises its own errors); an empty or `/`-prefixed `FilePath` is refused (a local Bot API server returns absolute paths); the URL comes from `file.URL(b, nil)`, so `API_SERVER` is honoured and the URL is never logged; the GET uses `raidAIFileHTTPClient` (10 s timeout, `CheckRedirect` returning `http.ErrUseLastResponse`, a package variable only for tests); a transport error is rebuilt as `fmt.Errorf("telegram file download: %w", ue.Err)` from the `*url.Error`, a bad status as `fmt.Errorf("telegram file download: status %d", code)`, a request that cannot be built as a plain `errors.New`; the body is read through `io.LimitReader` to 5 MiB plus one byte and refused when longer; the MIME type comes from `http.DetectContentType` on the bytes, and only image/jpeg, image/png and image/webp are kept.
- Gemini client (`raidAIGeminiClient`): built per job from `config.AppConfig.GeminiAPIKey` and `GeminiModel` with `raidAIGeminiEndpoint` (default `gemini.DefaultEndpoint`) and `raidAIGeminiHTTP`, package variables only so tests point them at an `httptest` server; the call uses a context from the pool context, so the drain aborts it.
- The bar `raidAIImageBar = 0.85` is a code constant (D-04), named in 07-SPIKE.md as the first thing the owner tunes.
- Outcomes: `errors.Is(err, gemini.ErrBlocked)` counts `raidAIBlocked` (a new counter and `RaidAIStats.Blocked`), any other error counts failed, and an answer with a verdict counts checked and then kept below the bar or spam at or above it, spam calling `raidAIRecordVerdict`. Download and `getFile` failures are failures of the job only (plan 07-09's Gemini breaker never counts them). A verdict whose `ModelStage` is LEGACY, DEPRECATED or RETIRED logs one warning per process naming the model id and stage. Logs carry chat, user and message IDs, the media kind and the HTTP status only.
- Watcher route: after the sender check, a message with a media reference is an image candidate when `raidAIImageConfigured()`; then Redis, settings, the candidate script with an empty hash (new member only), `aispamCarvedOut`, and an image job in the shared pool (D-18).
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet -tags testtools` and `gofmt -l` stand in for `make lint`.
