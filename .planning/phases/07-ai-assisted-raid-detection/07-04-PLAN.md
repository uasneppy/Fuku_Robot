## Decisions taken here (Claude's discretion, recorded)

- Migration `20261029120000_add_raid_detection_ai.sql` (greater than the latest, 20261018130000): two `ALTER TABLE chat_raid_detection ADD COLUMN IF NOT EXISTS` statements, `ai_enabled BOOLEAN NOT NULL DEFAULT TRUE` and `ai_threshold INTEGER NOT NULL DEFAULT 5 CONSTRAINT chk_chat_raid_detection_ai CHECK (ai_threshold BETWEEN 3 AND 500)`. The inline constraint keeps the statement idempotent (PostgreSQL has no `ADD CONSTRAINT IF NOT EXISTS`). Existing rows backfill to (true, 5). No top-level transaction statements and no concurrent index builds. `alita/db/migrations/runner.go` and `scripts/migrate_psql.sh` are generic appliers and need no change; confirmed in the acceptance criteria.
- The model's booleans keep no GORM `default:` tag (a Go false would become the SQL default on Create); the defaults live in the migration and in `raiddetection.Defaults`, which now sets `AIEnabled: true, AIThreshold: DefaultAIThreshold` so a chat's first write of any trigger inserts a row that satisfies the new CHECK.
- Stale cache guard: `GetSettings` normalises the value the cache-or-load call returns (not only the loader): `AIThreshold == 0` means "not populated" (the CHECK guarantees stored rows are at least 3), so it becomes `AIEnabled = true, AIThreshold = DefaultAIThreshold`. Cached values are unmarshalled fresh on every read, so mutating the returned value is safe.
- Writers: `SetAIEnabled` (columns `ai_enabled, updated_at`) and `SetAIThreshold` (`ai_enabled, ai_threshold, updated_at`, a threshold also turns the trigger on, `ErrThresholdOutOfRange` before any write), both through the existing `upsertSettings`, which ends with `cache.DeleteCache`. The key `raid_detection:*` is already in `skipLocal`; no change. The table stays out of backup, export, import and reset.
- Test fixtures that create `ChatRaidDetection` rows directly (alita/db/raiddetection/stats_test.go, alita/db/devs/repository_test.go, seedRaidSettings in alita/modules/raid_join_surge_test.go) would violate the new CHECK with `AIThreshold` 0 (GORM builds the CHECK from the model tag on SQLite too, as alita/db/constraints_test.go shows), so they set the AI fields; seedRaidSettings fills `AIEnabled: true, AIThreshold: 5` when its caller left AIThreshold at 0, keeping the existing callers unchanged.
- The counter reads the settings under `raidSettingsTimeout` like the flood watcher; a read error counts nothing (logged at debug), an off switch counts nothing.
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet -tags testtools` and `gofmt -l` stand in for `make lint`. The migration runs on PostgreSQL only in CI's migration chain.
