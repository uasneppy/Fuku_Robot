<objective>
The bot learns the owner's Gemini key and model, and the key can never be logged. `GEMINI_API_KEY` and `GEMINI_MODEL` join the config beside `TYPESAFE_API_KEY`; the key is registered with `logredact.RegisterSecret` together with the other secrets (PLAT-02), a structural pattern scrubs any Google-key-shaped string as a backstop, and the model name is checked against the client's allow-list before anything uses it. Without the key the whole image path stays inert and no image leaves the server (D-11, D-21). The environment docs and `sample.env` say what is sent where and recommend a paid-tier key.

Task 1 is the config fields, the default, the validation and the registration. Task 2 is the structural pattern and the two documentation files.

## Phase Goal

**As a** group admin, **I want to** have AI flag borderline spam text and images, **so that** subtler raids still trigger a lockdown.

**This slice:** the owner sets one environment variable to turn the image checks on, and the key never shows up in logs.

## Decisions taken here (Claude's discretion, recorded)

- The registration moves into a small helper `registerSecrets(cfg *Config)` called from the config `init()` where `logredact.RegisterSecret` is called today, so a test can prove the Gemini key is registered without loading a whole config. The list keeps every existing secret and adds `cfg.GeminiAPIKey`.
- The model check lives in `setDefaults` and uses `gemini.DefaultModel` and `gemini.ValidModel` from plan 07-02, so the config and the client share one rule; the warning quotes the rejected value with `%q` and says the default is used. `alita/utils/gemini` imports only the standard library, so this import adds no cycle.
- The structural pattern is `AIza[0-9A-Za-z_-]{35}` replaced by the placeholder; it is a backstop, the registered exact value is the real control (research assumption A11).
- No `GEMINI_MAX_PER_HOUR` style variables: the hourly budgets are code constants (D-20), and env overrides are deferred.
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet -tags testtools` and `gofmt -l` stand in for `make lint`.
