<objective>
The rule of "Undo everywhere", test-first, as one pure decision table: given the original action, the target's recorded prior state in a group, what the action left behind and the target's live state now, decide the one Telegram call that puts the prior state back, or the reason to leave the group alone. It sits next to decideStaffAction and does not change it.

This is the security core of undo (research Pitfall 4): restoring a prior restriction sends restrictChatMember to a kicked target, which Phase 2 forbids everywhere else. The table allows it only when the live state equals what the staff action left, and an invariant test proves that over every combination. Plan 03-06 calls this table from the undo run; plan 03-08 proves the restores end to end against the stateful fake.

Purpose: D-02 (restore the prior state, never just lift), D-04 (skip a group whose state changed since), STAFF-11.
Output: new types, constants and reasons in staff_action_decide.go and a table plus invariant test file.
</objective>

## Phase Goal

**As a** staff member, **I want to** log, list and undo every staff action, **so that** mistakes can be reversed and we stay accountable.

**This slice:** the decision behind every undo call, proven case by case before any undo touches Telegram.

## Decisions taken here (Claude's discretion, recorded)

- `staffUndoVerdict` embeds `staffVerdict` instead of adding fields to it: Phase 2 tests build `staffVerdict` with unkeyed literals (`staff_action_decide_test.go:42`), so that type must not change (research Pitfall 8).
- The left-behind check for a mute does not compare membership: a muted member who left keeps the same restriction, and membership is not a staff decision. The restriction (muted, same end date) is what must match. This is narrower than research's sketch on purpose; the unmute it leads to is the same call decideStaffUnmute already allows on a restricted non-member.
- A ban or mute whose own end date has passed is skipped as skip_restriction_ended before the left-behind check: Telegram lifted it already, so there is nothing to undo, and "changed since" would mislead.
- A restricted prior with no stored permission set cannot be restored exactly, so it is skip_no_prior_state rather than a guessed full mute.
- staffUndoMinRemaining is 120 seconds (research A6): a prior end date closer than that is treated as ended, so a pacing wait or a 429 retry can never turn a restore into a permanent restriction (Telegram's 30-second rule).
- "Not applied originally" (D-03) is decided by the caller before any Telegram read, because it needs the original row's outcome, not live state; the reason constant is defined here with the others.
