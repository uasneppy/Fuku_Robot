<objective>
Each entry of the Recent actions list opens its full record: every linked group's outcome in the run summary's own ✅/⏭/❌ format, plus the undo outcome once there is one. The detail view reads only the audit record and the current link list; it makes no Telegram call to linked groups.

Task 1 adds the per-entry buttons, the detail renderer and callback, and the record-to-summary mapping that plan 03-06's undo also uses. Task 2 covers the no-longer-linked marker, the undo outcome block with every undo reason worded, unfinished records, overflow, forged record IDs and the callback budget.

Purpose: ROADMAP Phase 3 success criterion 3 ("the outcome in each group"), SETUP-09, D-15.
Output: detail view in staff_history.go, record mapping helpers, reason texts for the undo reasons, locale keys in 7 locales, tests and the AGENTS.md callback rule.
</objective>

## Phase Goal

**As a** staff member, **I want to** log, list and undo every staff action, **so that** mistakes can be reversed and we stay accountable.

**This slice:** for any recent staff action, staff can see exactly what happened in each group, and what an undo did.

## Decisions taken here (Claude's discretion, recorded)

- The detail view is one edited message. Continuation messages belong to run summaries, not to browsing, so overflow ends with an explicit "N more group(s) not shown" note (research Open Question 2).
- Entry buttons are labelled with the entry's number in the list (the line starts with the same number), five per row, so ten entries cost two rows.
- Unlinked groups are detected by comparing group_chat_id with ListLinksByStaffFresh(staffChat); the stored title at action time is always shown.
- The wording for the eight undo reasons lands here, because the detail view is the first place an undo outcome is rendered; plan 03-06 reuses it for the undo summary.
