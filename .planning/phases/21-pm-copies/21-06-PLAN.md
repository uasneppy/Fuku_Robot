## Phase Goal

**As a** group owner, **I want** the bot to also tell a punished person in private, from settings I set group by group in the bot's private
chat, **so that** they know what happened and why, while the punishment and the group message are never delayed or changed.

After this plan a person the bot could not reach can still read their copy, and only they can.

<objective>
The Details button (PMSG-04, D-19, D-20, D-24): a short-lived Redis record of an undelivered copy, the edit that adds the button to the group
message through the private copies' pacer, the `pmcopy_` deep link that shows the record only to the punished person, and the hub's private
copies block with its Details toggle.

Purpose: PMSG-04 as an engine feature every event with a private copy gets.
Output: one new production file, engine and page changes, strings, tests, AGENTS.md.
</objective>

## Planner assumptions and decisions (flagged)

- **When (D-18, D-19).** `runEventPM` calls `pmCopyAddDetails` after a final outcome other than delivered, only when `o.Options.PMDetails` and
  `o.GroupMsgID` is set; a shed or capped copy never reaches it. `offerReplyPM` fills `Options` from the same `eventmsg.Get` result, `GroupMsgID` and
  `GroupRows` from the group step: the default and the refusal fallback carry `eventBotRows(r.Opts)`, a custom message the rows of its composed
  keyboard; Silent and a failed send leave `GroupMsgID` zero.
- **The edit.** `pmCopyAddDetails` returns quietly (one Debug line with the chat and user IDs) when the Redis client is nil, `getBotUsername` is empty,
  or the group rows already hold 100 buttons; it writes the record (`SET` with `pmCopyDetailsTTL` under `raidRedisTimeout`; an error stops it), then
  makes one `editMessageReplyMarkup` of `(chat, GroupMsgID)` through `pmCopyPaced` with a fresh copy of the rows plus the Details row (the group
  translator's `eventmsg_btn_details`). A failed edit (the message deleted by its Bot messages timer, a 429, a 5xx) is one Warn line with the chat ID
  and the Telegram code; the record stays until it expires. The edit is not a reply (D-31).
- **The deep link (D-20).** `pmCopyDetailsDeepLink` answers with `msg.Reply` like the other deep link handlers (inside the handler, not a goroutine):
  for a malformed payload, a missing record, a record whose `u` is not `user.Id`, an unparsable record and a Redis error, one reply
  `eventmsg_pm_details_none` in the opener's language (`lang.GetLanguage(ctx)`); for the punished person, the stored copy sent to their private chat
  with `media.SendGreetingMessage` (no header, no reply target). The record is not deleted on a view. No line logs the token.
- **The hub (D-24).** Body after the families: a blank line, `📩 <b>` + `settings_msg_pm_title` + `</b>`, one `settings_main_state_line`-style line per
  option (`settings_msg_line_pm_details` with `{state}` = `settingsStateWord`), a blank line and `settings_msg_hint_pm_options`. Keyboard: the family
  cells, one full-width toggle per option (`settings_btn_msg_pm_details`, `{state}` = `settingsStateIcon`, data `a=ho&t=d&v=<opposite>`), Back and
  Close: rows `[1 1 2]` after this plan (`[1 1 1 2]` once plan 21-07 adds the log row). The block is drawn only while some event has a spec.
- **The option's redraw.** `settingsMsgRunPMOption` writes through the option's `Apply` (no same-value shortcut: the value is absolute) and redraws the
  hub from a fresh read with no notice; a failed write redraws with `common_settings_save_failed`.
- **Bot username in tests.** The site's bot gets the username `FukuTestBot` (as `newSettingsMsgEnv` does) so the URL can be built; a subtest clears it to
  prove the "no username" branch.
- **English drafts:** button `📩 Details`; neutral reply `There is nothing to show here.`; line `Details button: {state}`; toggle `{state} Details button`;
  hint `Details button: when a private copy cannot reach someone (they never started a chat with me, or blocked me), I add a Details button to the
  group message. Only that person can open it and read their copy.`
