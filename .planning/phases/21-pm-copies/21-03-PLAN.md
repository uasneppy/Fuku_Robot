## Phase Goal

**As a** group owner, **I want** the bot to also tell a punished person in private, from settings I set group by group in the bot's private
chat, **so that** they know what happened and why, while the punishment and the group message are never delayed or changed.

After this plan a private copy that cannot be delivered changes nothing else, and no burst, raid or Staff Group action can turn into a stream
of private messages.

<objective>
The private copy's failure rules and limits (D-13 to D-18, D-33): classify every outcome by Telegram's code, replace a refused custom copy by
the default once, never send to an impossible target, cap automatic events per group per minute (fail closed), shed when the pool is full,
prove the pacers are independent, guard the engine's callers structurally, and keep every log line to IDs.

Purpose: PMSG-02, PMSG-03 and PMSG-05 hold for every event that will ever register a private copy, before any screen lets the owner switch
one on.
Output: the engine's failure paths, four tests, the caller guard, AGENTS.md.
</objective>

## Planner assumptions and decisions (flagged)

- **Where the checks run.** `offerEventPM` returns at once for a target `pmCopySkipTarget` refuses and for an event with no spec, then takes the
  pool slot (a full pool sheds). The cap is the job's first step, so the handler never makes a Redis call for a copy: for an `Automatic` spec,
  `pmCopyCapAllow` false ends the job with one Debug line and nothing else (D-18: no Details button, no log line from plans 21-06 and 21-07).
- **Classification (D-15).** `nil` delivered; code 403 blocked; `isTelegramClientError(err)` (a 4xx other than 429) or `errors.Is(err,
  media.ErrNoPermission)` refused; `errors.Is(err, ratelimit.ErrRateLimited)` or code 429 busy; anything else unknown. A refused custom copy sends
  `Fallback` once (text alone, `db.TEXT`, no keyboard, through `pmCopyPaced`) and its outcome is the job's final outcome; a refused default is final.
  Blocked logs at Debug; refused, busy and unknown at Warn; each line names the chat ID, the user ID, the event, the class and the Telegram code
  (the code only, `memberReqErrText`-style), never the error's description.
- **The cap is automatic events only.** The seven manual specs are `Automatic: false`, so no manual copy reads Redis for the cap. The cap is proved
  through a test-only automatic event (`withTestEventPM`) and a direct `offerEventPM`.
- **Fail closed (D-17).** No Redis client, or any Redis error, refuses an automatic copy. A manual copy needs no Redis (the pacer falls back to its
  local interval).
- **The guard (D-33)** follows `TestNoRawNewCommand` and `TestCommandRepliesStayInsideTheHandler`: parse every non-test `.go` file of `fuku/modules`
  with `go/parser`, collect the files that call `offerEventPM` (allow-list: `event_message.go`), that call `registerEventPM` (allow-list:
  `event_message_pm.go`), and fail when a file whose base name starts with `staff`, `lockdown` or `raid` contains any identifier `offerEventPM`,
  `registerEventPM`, `offerReplyPM`, `replyEvent` or one starting with `pmCopy`. Each allow-list entry carries a reason, and a stale entry fails, as in
  the replies guard. Later phases add their callers to these lists.
