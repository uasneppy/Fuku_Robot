# Phase 15 - UI Design Contract

> Visual and interaction contract for the AI spam-name rule, the eighth and last member requirement. It covers the
> eighth cell and rule screen of the Member requirements page, the "AI not configured" status (MREQ-10, completed
> here), the refusal of a punishing AI press while the AI is not configured, the AI phrase, remedy sentence and
> "I fixed it" answers of the group notice, every new callback with its worst-case size, every new string with its key
> and ceiling, and the checks that prove it.
> Generated by gsd-ui-researcher; to be verified by gsd-ui-checker.
> Upstream: 15-CONTEXT.md D-01..D-18 (locked, not reopened), REQUIREMENTS MREQ-01, MREQ-10, MREQ-14, PLAT-05 and
> PLAT-06, ROADMAP Phase 15, the APPROVED Phase 14 contract (`14-UI-SPEC.md` and `14-UI-CHECK.md`, whose structure,
> section order, check list, string-table style, worst-case callback table, row budget table and amendment style this
> file copies), the Phase 13 contract (`13-UI-SPEC.md`), AGENTS.md (Callbacks `settings|v1` and `mreq|v1`, the Member
> requirements page bullet with the status block and `settingsMreqChannelGate`, Permissions, the member requirements
> Subsystem traps) and the code of `fuku/modules/settings_mreq.go`, `memberreq_rules.go`, `memberreq_notice.go`,
> `memberreq_fixed.go`, `raid_ai.go`, `locales/en.yml` (`settings_mreq_*`, `settings_btn_mreq_*`, `mreq_*`) and
> `fuku/i18n/settings_locale_test.go` and `memberreq_locale_test.go`.

This phase has no web screen. Everything is a Telegram message in HTML parse mode plus an inline keyboard, on the same
two surfaces as Phases 13 and 14: the settings menu (private, or opened in the group, edited in place) and the group
(the notice and its edit). This contract **extends** the Phase 13 and 14 contracts. **Anything not restated here is
unchanged and applies to the eighth rule**: the message anatomy, text styling, the press pipeline
(`settingsPress.verify`, owner gate at step 4b, one answer per press), the rule screen's shape, the two-tap card
(`settings_card.go`), the rights (`settingsRightAdmin` to open, `settingsRightRestrict` to choose), the notice anatomy,
the "I fixed it" order (steps 1 to 10 as Phase 14 left them), the "never name the Staff Group" rule (D-21, D-32 of the
settings menu; D-16 of Phase 13) and the Phase 11 to 14 limit tables.

The page is registered from `settings_mreq.go` and `settings_pages.go` is not edited. All eight rules are Off by default
and nothing is preselected (D-06).

## Message Layout (replaces Spacing Scale)

The Phase 9 anatomy and the Phase 13 and 14 page, rule screen, card and notice anatomy stand. This phase changes four
things: one more rule line and one more grid cell, one more optional status line on the page, the AI rule screen (two
forms), and the AI card text.

### The Member requirements page (page `m`), new shape

```
⚙️ Settings · Requirements            <- settings_header + settings_page_mreq
Fuku Test Group  -1001234567890       <- group line, unchanged
<blank>
<intro line>                          <- settings_mreq_intro (unchanged)
<all-off line, only when every rule is Off>   <- settings_mreq_all_off (unchanged)
<blank>
Must have a last name: 🔇 Mute        <- one line per rule, fixed order, settings_mreq_line
Must have a username: ❗ Warn
No Russian name: ❌ Off
No Arabic name: ⛔ Ban
No Chinese name: ❌ Off
Must have a profile photo: 🔇 Mute
Must subscribe to the channel: ❗ Warn
No AI-flagged spam name: ❗ Warn      <- NEW, settings_mreq_rule_ai
<blank>
Check on join: ✅ On                  <- unchanged
Delete messages: ❌ Off
<blank, only when a status line follows>
🚫 Must subscribe to the channel: I am not an administrator of the linked channel, so nobody is checked.
                                      <- the group-level line (0 or 1), unchanged
🚫 No AI-flagged spam name: AI checks are not set up on this bot, so nobody is checked.
                                      <- NEW, the AI line (0 or 1), appended last, see section 3
<blank>
<hints, unchanged: letters, blank last name, lookup, join, delete, mute>
<blank, only with a notice>
<notice line>
```

The rule order is the order of the code's rule table, now: last name, username, Russian, Arabic, Chinese, profile photo,
channel, **AI** (`ai`, bit 128, `memberreq.RuleAI`, column `ai_action`). The new row is appended; the next free bit is
256. The cannot-work block is the Phase 14 list of lines (`settingsMreqHereLines`): the AI line is appended to that list
and no hint, switch line or row moves. No page hint is added (D-16).

### Keyboard of the page, in order

1. **Rule grid:** eight cells in rule order, two per row filled left to right, **no odd last cell**: `[ln, un]`,
   `[ru, ar]`, `[zh, ph]`, `[ch, ai]`. A cell is `{punishment icon} {short rule name}` (amendment M14); a press opens that
   rule's screen (`a=mo&t=<code>`).
2. **Switch row:** `[ {✅|❌} Check on join | {✅|❌} Delete messages ]`, unchanged.
3. **Navigation row:** `[ ⬅️ Back | ✖️ Close ]`, unchanged (Back opens Main).

No Open in private row, in either menu (nothing awaits typed input). The two menus differ only by the owner field of
the callbacks. The icon on the AI cell is `memberReqActionIcon` of the stored value, like every other rule cell: it shows
the stored punishment even while the AI is not configured (the page body's line, not the icon, says it is inert).

### The AI rule screen (`t=ai`)

The Phase 13 shape: name, description, the rule's own hint (`HintKey`, right after the description with no blank line),
one status slot, a blank line, `Punishment:`, then the hints and rows. Opening it makes **no status-read Telegram call and no other
network call** beyond the press pipeline's own live checks (M17). Two forms:

**Configured (`ENABLE_AISPAM` on and an Anthropic key set): the usual three-row shape.**

```

<blank>

<blank>
<choose hint>                         <- settings_mreq_choose_hint
<actions hint>                        <- settings_mreq_actions_hint
<blank, only with a notice>
<notice line>

[ Off | ✅ Warn ]
[ Kick | Ban | Mute ]
[ ⬅️ Back | ✖️ Close ]
```

**Not configured: the Off-only form (amendment M15), in every group type.**

```
⚙️ Settings · Requirements

<blank>
No AI-flagged spam name
<description>
<hint>
🚫 No AI-flagged spam name: AI checks are not set up on this bot, so nobody is checked.
<blank>
Punishment: ⛔ Ban                    <- a stored value stays visible: it is inert, and Off turns it off
<blank, only with a notice>
<notice line>

[ Off ]                               <- ✅ Off when the stored value is Off
[ ⬅️ Back | ✖️ Close ]
```

The status slot holds **one line**: configured, none in a supergroup and the basic-group line in a basic group; not
configured, always the AI line (M16). A stored non-Off value while not configured is **inert** (the lookup answers
inert, never unknown, so it also defers no weaker punishment: `memberReqUnknownDefers`), and Off clears it. The form
is chosen by the process fact alone, never by a read, so the screen cannot show `❔`.

### The confirm card

Kick, Ban and Mute on `ai` draw the Phase 13 card: `settings_mreq_confirm` with the rule's `settings_mreq_rule_ai` name
and the option word, a blank line, then **`settings_mreq_confirm_ai_kick | _ban | _mute`** in place of the generic
consequence (amendment M19), `[ ✅ Yes | ❌ No ]`, `[ ⬅️ Back | ✖️ Close ]`. Two rows. The card is drawn only after the
configuration check passed (section 5). Warn and Off write at once.

### The group notice

Unchanged in shape and in every template. The AI rule adds one more phrase to `{rules}` and one more trailing sentence
(section 7). One paragraph, no header, no chat ID, no channel title, **no name that was judged**.

### 3. "Cannot work here" and the AI status (MREQ-10; D-14)

One condition, one line of words, never an identifier: **AI not configured** = `config.AppConfig.EnableAISpam` false or
`config.AppConfig.AnthropicAPIKey` empty, the very condition of `raidAIImageConfigured()` in `raid_ai.go` (that function
has only this configuration half; it reads no Redis). `ANTHROPIC_MODEL` invalid or empty is **not** "not configured": the
claude package falls back to `claude.DefaultModel` with a warning.

| Surface | Line (key) | Shown when |
|---------|------------|------------|
| Page body | `🚫 ` + `settings_mreq_here_ai` (`{rule}` = `settings_mreq_rule_ai`) | the AI rule is **not Off** and the AI is not configured; appended after the group-level line |
| AI rule screen slot | the same line | the AI is not configured, **whatever the stored value is** (the screen exists to explain) |

Composition with the basic-group and channel lines (amendment M16), exhaustive:

| Group | AI configured | AI rule stored | Page body lines | AI screen slot | AI screen form |
|-------|---------------|----------------|-----------------|----------------|----------------|
| supergroup | yes | any | channel line only if the channel rule is on and has one | none | three rows |
| supergroup | no | Off | channel line only if the channel rule is on and has one | AI line | Off-only |
| supergroup | no | not Off | that channel line (if any), then AI line | AI line | Off-only |
| basic group | yes | any | basic-group line only while some rule is not Off | basic-group line | three rows |
| basic group | no | Off | basic-group line only while some rule is not Off | AI line | Off-only |
| basic group | no | not Off | basic-group line, then AI line | AI line | Off-only |

Rules for the lines:

- **One basic-group line.** The basic-group line is still rule-agnostic and appears once on the page and on every rule's
  screen but the AI screen while the AI is not configured. A basic group is never screened (the message watcher's
  filter is supergroups only, AGENTS.md), so with the AI configured the AI screen in a basic group shows the basic-group line and the usual
  three rows (a stored value is harmless and inert, Phase 14 A2).
- **The AI line wins on the AI screen** because Off-only form and slot line must explain each other: Off-only holds exactly
  when the slot is the AI line. The basic-group fact is still on the page body and on every other screen.
- **The page lists a problem only for a rule that is not Off**; with the AI rule Off an owner learns the AI is not
  configured by opening the AI screen, where the line is always shown.
- **Nothing is claimed that the code does not do.** "So nobody is checked" is the inert answer of the lookup (D-14, D-08).
  No line says a key, a variable, a model or a provider's name; the hint (not the line) names Anthropic's Claude.
- **No identifier.** No line names a chat ID other than the group line's, the linked channel, the Staff Group or a member.
- **No "unknown" line** (M22). A Redis outage, a paused breaker, an exhausted budget and a failing provider are not
  shown on the page.

### 4. Choosing a punishment for the AI rule (D-06)

Phase 13 section 2 applies unchanged to `ai`: five choices as `st` presses with the absolute `v`; Off and Warn write at
once through `applyMemberReqAction(ctx, chatID, rule, action)` (the rule `memberreq.RuleAI`, column `ai_action`, a Go 0
written, the cache key dropped by the repository, the row read back); Kick, Ban and Mute draw the card and write nothing
until Yes; a press of the stored value (judged on the direct fresh database read `settingsMreqFresh`) writes nothing
and draws no card; a failed write redraws the rule screen with `⚠️ common_settings_save_failed`. The hint recommends
Warn or Mute over Kick or Ban and **hides nothing**: all five stay selectable while the AI is configured, and the page
never preselects (D-06). The recommendation never names Ban as a good choice.

### 5. Refusing a punishing value while the AI is not configured (D-14)

The Off-only form offers `[Off]` alone, so a punishing press reaches the bot only from a stale screen (the menu message
outlived a restart that removed the key, or the switch), a stale card or a forged callback. It is refused, with an alert,
by a **pure check that runs after every existing step** and makes **no network call of any kind** (the AI counterpart of
`settingsMreqChannelGate`):

| Order | Step (an `st` on `ai` with `v` 1..4, and the card's `my` on `ai`) |
|-------|-------------------------------------------------------------------|
| 1 to 5 | the whole press pipeline: strict decode, service identity, group-menu opener, live `getChatMember` of the presser, owner gate, right `settingsRightRestrict` (a Yes also checks `e`, and an expired Yes redraws the rule screen with `⚠️ settings_card_expired`, no configuration check) |
| 6 | the fresh same-value database read (a press of the stored value writes nothing, draws no card, makes no configuration check) |
| 7 | the configuration check: `ENABLE_AISPAM` and the Anthropic key, in-process, nothing else read |
| 7a | **not configured:** answer the alert `settings_mreq_here_ai` (the status line's own key, with `{rule}`, no icon: plain text, at most 200 characters rendered, 84 as written in English and 164 at the ceilings), write nothing (no repository call, no cache write), draw no card (a Yes replaces its card) and **redraw the AI screen** in its Off-only form so the stale screen is repaired. No notice line is added (the redrawn 🚫 line already says it). The alert is the press's one answer |
| 7b | configured: continue as Phase 13 (Warn writes; Kick, Ban, Mute draw the card, whose Yes runs steps 1 to 7 again) |

Off (`v=0`) never makes the check, so an administrator can always clear a stored value. There is **no unknown branch**,
unlike the channel gate: the fact is process-level and always decided. The check never reads Redis or the group type
(a basic group with the AI configured proceeds). It costs no new key (the status line's key is the alert). Only one gate
applies to a press, because it names one rule.

### 6. Rights and stale state

| Press | Right | Refusal |
|-------|-------|---------|
| open the page, open the AI screen (`mo`), Back, the card's No | `settingsRightAdmin` | pipeline's own |
| a punishment choice on `ai` (any `v`), the card's Yes (`my`) | `settingsRightRestrict` | alert `settings_no_restrict`, nothing edited or written |

- **Two-tap card.** Only Kick, Ban and Mute. The card binds nothing about the configuration: Yes re-runs the whole

### 7. The group notice and the answers (MREQ-14; D-15)

Every Phase 13 and 14 template is **unchanged**. This phase adds one phrase, one trailing sentence and uses the existing

**Phrase (the grammar slot).** `{rules}` is a comma-joined list of noun phrases that complete "you are muted:", "was
