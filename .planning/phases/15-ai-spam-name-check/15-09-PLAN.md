## Planner assumptions (flagged)

- Execution rules are `executor-brief-15.md`'s; read "of NN" as "of 11". This plan depends on 15-02 (`ClassifyNames` and `namecanon`) for code; it sits after the page plan by execution order and because both edit `AGENTS.md` (file ownership: one writer at a time).
- The names mode reuses the image mode's pure functions and does not copy them (dupl): it builds `result` values (the `File` field holds the row number as text, never a name; `Label` is spam or ham; `Probability`, `Duration`, token counts, `Blocked`, `Failed`, `Finish` as for images) and calls `summarize`, `sweep` (with a names-specific list of bars: 0.5, 0.7, 0.8, 0.85, 0.9, 0.95, 0.97), `percentile`, `totalsOf`, `estimateCost`, `costPer1000` and `writeSummary`. The false-positive rate (false positives over false positives and true negatives) is computed in `names.go` from the existing `summary` fields and printed as one extra line by the names mode only, so the image summary text, which the existing tests pin, is unchanged. The existing `TestSpike*` tests are not edited.
- A row the bot would send nothing for (`namecanon.Of` false: all three strings empty, or a lone Deleted Account) is not sent and is counted as "not judgeable", like a bad row; the CSV reader counts bad labels, wrong column counts and rows over the cap. The tool's source comment on imports is updated: it now imports the claude package and the leaf `namecanon`, both free of the pre-main database connection.
- The names mode prints names only in the owner's CSV (stdout, or the `-csv` file): the row's three strings are echoed there so the owner can review a misjudged row; stderr and every error line carry row numbers and counts, never a name, and the key never appears anywhere (the existing contract; a server that echoes the key in an error body must not leak it).
- `-repeat` judges each row N times in sequence per worker; the statistics are per row (minimum, maximum, spread), the count of rows whose repeats lie on both sides of the bar, and the largest spread; with N of 1 no repeat line is printed. Latency and token totals count every request. A row with a failed or refused repeat is excluded from the stability statistics and counted.
- `15-SPIKE.md` follows `14-SPIKE.md` (the opening statement that nothing blocks, the pre-enable section, what the tests prove and cannot, before you start, numbered checks each with steps, "Pass looks like" and "If not", follow-ups, accepted limits). It is written here in full from research S-11 and the plans' facts; plan 15-11 reads it once more against the finished code and corrects it if anything changed. It records no result: the live spike is the owner's (D-18). It must say plainly that with no key the AI rule is off and the page says so.
- Test hygiene: tests run `run()` against an `httptest` server on loopback (no real provider, no network), with a fake getenv holding a fake key, and write CSV files into `t.TempDir()`; no test is skipped; the tool has no global state a test must restore beyond what the existing tests already handle.
