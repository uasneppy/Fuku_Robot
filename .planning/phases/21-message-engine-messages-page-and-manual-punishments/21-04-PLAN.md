## Phase Goal

**As a** group owner, **I want** to set what the bot says in a group when an admin bans, kicks, mutes, unbans or unmutes someone, from that group's settings in the bot's private chat, **so that** the replies sound like my community, while a group that sets nothing sees no change.

After this plan a ban message stored for a group is what the next `/ban` posts there; every other group, and every other command, is unchanged.

<objective>
The phase tracer (D-08 to D-15): one event end to end. Build the event message engine in `fuku/modules/event_message.go` (read the group's stored message after the punishment, Silent, the default fallback, the renderer with the Welcome and event placeholders, the composition with media and buttons, the refusal fallback, the deletion queue) and route the ban event (`/ban` and `/dban`) through it, with the ban's default reply extracted into a builder that produces today's bytes.

Purpose: prove storage, cache, engine, send path, fallback and deletion timer on one command before the other six events (21-05) and the page (21-06 onward).
Output: the engine, the ban send site, its tests, one locale key, AGENTS.md.
</objective>

## Planner assumptions and decisions (flagged)

- **One text, every language (D-02).** A stored text is sent as stored whatever the group's language; only the anonymous word `eventmsg_admin_anon` and the default reply are translated, both in the group's language.
- **The default stays where it is built.** The send site builds today's reply exactly as before (now through `banDefaultReply`, the same `Sprintf`, mention, reason line and Unban keyboard) and hands it to `replyEvent`; with no custom content `replyEvent` sends that text and those options through `replySuccess`, so the default path is literally today's call (`TestLegacyModerationRequests` proves it).
- **Order and timing (D-03).** `replyEvent` runs in the reply step of the moderation pipeline, after `execute` applied the punishment. The one read (`eventMessagesLookup` under `eventMessageReadTimeout`) is cached and in `skipLocal`; a read error is logged once at Warn with the chat ID and the event and the default is sent; Silent is honoured only from a successful read, so an unreadable row never silences a message.
- **Rendering (D-08 to D-11).** Only when the row's text is set: each event token is first replaced by a sentinel `<<fuku-event-NAME>>` (the stored text is HTML, where a literal `<` is always escaped, so a sentinel cannot come from the owner's text), then `formatting.FormattingReplacer` fills the Welcome placeholders for the target and the group and adds the `{rules}` button, then each sentinel is replaced by its escaped value in one `strings.NewReplacer` pass. So a reason that contains `{first}` and a name that contains `{reason}` stay as typed, and `{count}` in an event message is the event's own value (empty for the manual events), never the member count. Values: `reason` = `html.EscapeString(Reason)`; `admin` = the translated `eventmsg_admin_anon` when `actor.Anonymous` or `actor.User` is nil, else `html.EscapeString(formatting.GetFullName(first, last))`; `duration` = `html.EscapeString(Duration)`; `until` = `formatChatTime(Until, chatClockOf(chatID), "02.01.2006 15:04")` or empty for a zero time; `action`, `count`, `limit` and `window` are empty for the seven manual events. An unknown `{word}` of the owner's text stays as typed.
- **Composition.** With no custom text the text is `r.Default` (today's text, with its reason line) and only the media and buttons are custom. When `r.Note` is set (the `/unmute` lockdown note, plan 21-05) a custom text is followed by a newline and the note. The keyboard is the bot's own rows from `r.Opts.ReplyMarkup` (the Unban row of a ban) followed by `keyboard.BuildKeyboard` of the custom and rules buttons; with neither, no keyboard. The media is the row's file and type, `db.TEXT` when there is no file. The message is sent with `media.SendGreetingMessage` to the group with `ReplyMsgID` the command's message ID (`AllowWithoutReply` true, link previews off, HTML) and `ThreadID` the command's `MessageThreadId` when `IsTopicMessage`.
- **Refusal (D-13).** `eventMessageRefused(err)` is `isTelegramClientError(err) || errors.Is(err, media.ErrNoPermission)` (the media sender turns a Telegram permission refusal into `ErrNoPermission`). A refused custom message sends the default once through `replySuccess`; any other error is returned as today's send error is.
- **Anonymous actor (D-12).** `actorIsAnonymous(ctx)` is true when `ctx.Data[eventAnonActorKey]` is true (set by the proof tap in plan 21-05) or `ctx.EffectiveSender.IsAnonymousAdmin()` (an anonymous admin in a group whose AnonAdmin mode lets the command run at once, where `c.User` is the Group Anonymous Bot).
- **Not events.** The channel `/ban` and `/unban` replies (`bans_anonymous_ban_user`, `bans_anonymous_unban_user`) act on a channel, not a member, keep `replySuccess` and today's text whatever is stored (stated limit, recorded in AGENTS.md). `/sban` stays silent (D-14).
- Logging: no stored text, caption, button name, link or file ID is ever logged; lines carry the chat ID and the event key only.
