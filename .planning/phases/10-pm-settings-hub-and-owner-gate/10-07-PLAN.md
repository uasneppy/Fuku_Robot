## Phase Goal

**As a** group owner, **I want to** open my groups' settings from the bot's private chat and decide whether my admins may change them, **so that** I control who configures the bot.

After this plan the owner types `/settings` to the bot in private, sees their groups, taps one, and is in that group's menu, with a Groups button to go back.

<objective>
Add the private group list (the `shub|v1` namespace with `lp` and `cx`), the pick (`pk` inside `settings|v1`, through the whole press pipeline with the R3 class rule), the Groups button on a private Main page, and the group `/settings` repair path (D-01, D-02, D-03, D-04, D-07, D-14, D-18, D-20; research R-03, R-05.4, R-07 "Pick").

Purpose: MENU-09 (the private list and the pick), MENU-10 (the list comes from the record; the repair path), MENU-11 (the pick is gated), MENU-13 (a gated admin does not see the group; the empty list is one text for everyone).
Output: `settings_hub.go` and its tests, the private `/settings` branch, the pick in the press pipeline, the Groups button, the test rewrites and AGENTS.md.
</objective>

## Planner assumptions (flagged; UI-SPEC "UI Considerations" unresolved rows)

- **Page memory:** Groups returns to page 1; the page the user came from is not remembered, because the menu keeps no state. Accepted limit.
- **Duplicate titles:** two groups with the same title get identical buttons (D-01: title only); the Main page's group line (title and chat ID) tells them apart after the pick. The chat ID is added to the label only if the owner asks.
- **List size:** a 3-digit page value caps the list at 999 pages (7,992 groups); a user with more sees the last page as the limit. Accepted.
- **Private non-pick presses keep the Phase 9 step-4 mapping** (a forged `c` on `op`/`tg` can still meet the cannot-open edit), as the UI-SPEC scopes the class rule to the pick and the deep link (research Pitfall 7). Recorded in AGENTS.md as a known note.
