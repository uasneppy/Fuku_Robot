## Phase Goal

**As a** group owner, **I want** rules with media and buttons, media shown under its text, and members greeted only on their first join, **so that** my messages look and behave the way I set them.

After this plan "Delete last welcome" and "Delete last goodbye" never leave an old message behind when two joins or leaves reach two replicas at the same moment.

## Planner assumptions (flagged)

- A single `UPDATE ... RETURNING <old>` cannot return the previous value on PostgreSQL (RETURNING yields new values), so the swap is a short transaction (research S-02). The research suggested `clause.Locking{Strength: "UPDATE"}`; the SQLite dialector ignores it, and a deferred SQLite transaction that reads and then writes after another writer committed fails with a busy-snapshot error. To serialise on both databases, the transaction starts with a column-targeted no-op update of the column to itself (row write lock on PostgreSQL, database write lock on SQLite, both waiting under the busy timeout), then reads the previous value, then writes the new one.
- Droppable: no later plan depends on it; 12-16 checks whether `12-15-SUMMARY.md` exists and, if not, writes the known race into AGENTS.md and leaves `TestSwapCleanMsgIDConcurrent` out of the Makefile.
