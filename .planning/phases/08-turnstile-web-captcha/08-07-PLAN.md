## Phase Goal

**As a** group admin, **I want to** verify new members with Turnstile in a Telegram Mini App, **so that** bots stay out with little friction.

**This slice:** the member reads the check page in their own language, with the same meaning and tone in all seven.

## Decisions taken here (Claude's discretion, recorded)

- English text is exactly the UI-SPEC "Page strings" table. Translations follow its "Max other" lengths (counted in runes); when a translation is longer, shorten it, never truncate. The button labels (`captcha_web_retry_button`, `captcha_web_close_button`) stay one line. Present tense for what is happening, past tense for what the server did, as the copywriting contract says.
- Only the English kick bodies (`captcha_web_failed_body_kick`, `captcha_web_expired_body_kick`) contain the word "rejoin"; the test checks this in English only (a semantic check in six other languages is a native-speaker review item, listed in the validation strategy).
- `StringTable(langs, keys []string) (map[string]map[string]string, error)`: one GetTranslator per language (an unknown language resolves to English like every translator), one GetString per key; an error names the language and key, never a value.
- The max-length table lives in the test file keyed by page key, and the test fails when it does not cover exactly `captchaweb.PageKeys`; the i18n test importing `alita/utils/captchaweb` is fine, because that package imports nothing of this module.
