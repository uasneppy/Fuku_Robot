## Phase Goal

**As a** group admin, **I want to** verify new members with Turnstile in a Telegram Mini App, **so that** bots stay out with little friction.

**This slice:** a member who opens the Mini App sees one calm, readable screen in their language that tells them what is happening and what they can do, in light and dark themes and inside a 320 px sheet.

## Decisions taken here (Claude's discretion, recorded)

- `PageKeys`: the 26 page keys in the UI-SPEC table order (`captcha_web_page_title`, `captcha_web_loading_title`, `captcha_web_loading_body`, `captcha_web_ready_title`, `captcha_web_ready_body`, `captcha_web_widget_label`, `captcha_web_verifying_title`, `captcha_web_verifying_body`, `captcha_web_passed_title`, `captcha_web_passed_body`, `captcha_web_failed_title`, `captcha_web_failed_body_kick`, `captcha_web_failed_body_ban`, `captcha_web_failed_body_mute`, `captcha_web_expired_title`, `captcha_web_expired_body_kick`, `captcha_web_expired_body_ban`, `captcha_web_expired_body_mute`, `captcha_web_retry_title`, `captcha_web_retry_body`, `captcha_web_retry_button`, `captcha_web_invalid_title`, `captcha_web_invalid_body`, `captcha_web_unsupported_title`, `captcha_web_unsupported_body`, `captcha_web_close_button`). `PageLanguages`: `en es fr hi id pt ru`. The JSON block is `{"<lang>": {"<key>": "<text>"}}`; the script reads a key by dropping the `captcha_web_` prefix only in its own lookup helper, never by building key names from user input.
- `NewPage(PageOptions{SiteKey string; Strings map[string]map[string]string})` refuses an empty site key or an `en` table missing any of `PageKeys`, parses the template once and marshals the strings once. `ServeHTTP` answers GET and HEAD only (405 otherwise; the mux pattern does the same in production).
- Nonce: 16 bytes from `crypto/rand`, standard base64, put on the `<style>`, the i18n `<script type="application/json" id="i18n">`, both external `<script src>` tags and the main `<script id="captcha-main">`. `CSPFor(nonce string) string` builds the exact header value, so the test compares against one function, not a copy.
- The main script holds no template action, so `node --test` can extract it verbatim from the HTML; all server values reach it through `data-*` attributes on `<main>` and the JSON block. Its pure functions are exposed as `window.CaptchaPage` (`resolveLanguage`, `readChallenge`, `cdataFor`, `turnstileLanguage`, `stateForAnswer`, `parseColor`, `contrastRatio`, `widgetSizeFor`, `createSubmitLatch`), and booting waits for `DOMContentLoaded`, so the node test can load the script into a `vm` context with a stub `window` and `document`.
- Turnstile `language`: Cloudflare's supported-languages table (read by the research from Cloudflare's docs source) lists `en`, `es`, `fr`, `hi`, `id`, `pt` and `ru`, so the widget gets the resolved locale code and any other value maps to `auto` (D-24's rule for an unconfirmed code).
- The Turnstile script tag is `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit&onload=captchaTurnstileReady` with `async defer`; it is never proxied or cached (Cloudflare's rule). The widget is rendered once from `captchaTurnstileReady` after the Telegram object and a valid challenge are known.
- The optional `&mode=compact` link parameter and the `unsupported-callback` stay out (COVERAGE.md opt-outs, decided in the spike).
- Haptics (`notificationOccurred` success on passed, error on failed and expired) are feature-checked and optional, as the UI contract allows.
