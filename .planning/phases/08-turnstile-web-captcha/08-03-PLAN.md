## Decisions taken here (Claude's discretion, recorded)

- Future skew: `auth_date` up to 60 s ahead of `now` is accepted, more is rejected (research Pitfall 4). Older than `InitDataMaxAge` (5 minutes, D-02) is rejected, at exactly 5 minutes accepted.
- The raw string is capped at 4096 bytes before parsing (the verify handler caps the JSON field at the same size).
- A repeated key of any name (`url.ParseQuery` gives more than one value) is rejected, so parameter pollution cannot pick which value is signed.
- `is_bot` true in the user JSON is rejected; a missing `first_name` is allowed (the mention falls back like the existing captcha).
- Leaf rule for `captchaweb`'s non-test files: the standard library, `github.com/redis/go-redis/v9` and `github.com/sirupsen/logrus` only; any other import, a package of this module above all, fails `TestCaptchaWebPackageIsLeaf`. AGENTS.md already states the rule (plan 08-01); this plan adds the test that enforces it and changes no rule, so it does not edit AGENTS.md.
