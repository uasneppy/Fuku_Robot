## Phase Goal

**As a** group admin, **I want to** verify new members with Turnstile in a Telegram Mini App, **so that** bots stay out with little friction.

**This slice:** a member who fails the check is kicked once and can rejoin, a member who runs out of time is kicked once, and nobody is ever kicked because Cloudflare or the owner's setup had a bad moment.

## Decisions taken here (Claude's discretion, recorded)

- Classification (D-28): success true with every field matching is OutcomePass; success true with a cdata that differs is OutcomeFailed (ReasonCData, a token minted for another challenge); success true with a hostname or action that differs is OutcomeRetry (ReasonHostname or ReasonAction). success false is OutcomeFailed only when the error-codes list is non-empty and every code is invalid-input-response (ReasonInvalidToken) or timeout-or-duplicate (ReasonDuplicate); any other code present makes it OutcomeRetry with the reason of the first such code in this order: missing-input-secret or invalid-input-secret (ReasonSecret), internal-error (ReasonInternal), bad-request (ReasonBadRequest), missing-input-response (ReasonMissingResponse), anything else or an empty list (ReasonUnknown). So a member is failed only when the answer is provably about their token and nothing else.
- `Verdict.ConfigError()` is true for ReasonSecret, ReasonHostname and ReasonAction; the handler logs those at Error with the reason name only and no other field from Cloudflare.
- Rearm script (research Pattern 10): KEYS[1] the challenge hash, ARGV remaining ms, user, attempt, chat, expiry ms; does nothing when the key exists or the remaining time is not positive; else HSET of the four fields and PEXPIRE. Remaining = the PTTL that ConsumeIfUser returned minus the time since that call.
- Verify order after the consume (research Pattern 6 steps 7-9): Backend.BotCanRestrict with a 3 s context (false or error: re-arm, retry); Backend.Attempt (error: re-arm, 503 retry; not Live: Backend.Expire, then expired with the action); siteverify; OutcomePass: Backend.Pass (PassOK passed; PassLost: Backend.Expire, expired with the action; PassUnmuteFailed: Warn log, retry, no re-arm; an error before the claim: re-arm, retry); OutcomeFailed: Backend.Fail (claimed: failed with the action; not claimed: Backend.Expire, expired with the action; an error: re-arm, retry); OutcomeRetry: re-arm, retry. Fail, Expire and Pass run on context.WithoutCancel(r.Context()) with the 20 s deadline.
- Backend contract for "an error": the method returns an error only when it changed nothing (no claim, no Telegram write), so re-arming after it is safe.
- Modules: `Fail` = handleCaptchaTimeout(bot, chat, user, attemptID, 0, settings.FailureAction) returning its claimed flag; `Expire` = a fresh GetCaptchaAttemptByID; nothing when the row is gone or names another user or chat; expireCaptchaAttempt(bot, attempt) when now is at or past ExpiresAt; nothing otherwise (the timer owns a live row). `BotCanRestrict` = bot.GetChatMemberWithContext(ctx, chat, bot.Id) merged: creator, or administrator with CanRestrictMembers. The bot's own live check, never the admin cache.
