## Phase Goal

**As a** group admin, **I want to** verify new members with Turnstile in a Telegram Mini App, **so that** bots stay out with little friction.

**This slice:** the owner sets four variables (and optionally the proxy list); a half-finished setup fails loudly at startup instead of half-working, and the secret never reaches a log.

## Decisions taken here (Claude's discretion, recorded)

- Field names: `CaptchaWebBaseURL`, `TelegramMiniAppShortName`, `TurnstileSiteKey`, `TurnstileSecretKey`, `CaptchaWebTrustedProxies` (a raw comma-separated string; plan 08-08 parses it with `net/netip` in the captchaweb package). Env names exactly as D-11 plus `CAPTCHA_WEB_TRUSTED_PROXIES`. Values are trimmed of surrounding whitespace when loaded.
- `Config.CaptchaWebConfigured()` is true only when all four required values are non-empty; plan 08-10 registers the routes only then (D-10).
- Validation lives in `validateCaptchaWeb(cfg)`, called from `ValidateConfig`: none of the four set and no proxy list is fine; the proxy list set without the four is an error (a proxy list alone is a misconfiguration worth stopping on); some but not all of the four is an error `web captcha settings are incomplete: missing <names>` listing every missing name in a fixed order. Each other check returns an error naming its variable and the rule, never the value (the `setDefaults` note at config.go lines 467-474 is the model).
- The secret's minimum length is the redactor's floor (6, `minSecretLen` in `alita/utils/logredact`): a shorter value could not be scrubbed, so it is refused at startup. The short-name rule `^[A-Za-z0-9_]{1,64}$` is a loose superset of BotFather's (research A7).
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet` and `gofmt -l` stand in for `make lint`.
