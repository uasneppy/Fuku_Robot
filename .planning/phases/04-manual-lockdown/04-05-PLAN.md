<objective>
Join requests cannot be used to get around a lockdown, and a lockdown stays inside its own group. Requests that arrive during a lockdown are recorded and declined by the worker, auto-approve never sees them, and the bot's own Accept button refuses. Two locked groups never affect each other, and the old /antiraid join handler steps aside while a lockdown is active.

Task 1 is the tracer for join requests. Task 2 covers isolation between groups and coexistence with /antiraid.

Purpose: LOCK-01 for requests (D-06, D-25) and LOCK-04 (a lockdown affects only its group).
Output: the request handler and decline step, the Accept-button refusal, antiraid's step-aside, locale key, help text and docs, AGENTS.md rules.
</objective>

## Phase Goal

**As a** group admin, **I want to** lock my group down during a raid and lift it when safe, **so that** attackers are stopped and settings survive.

**This slice:** raiders cannot get in through join requests, and locking one group never touches another.

## Decisions taken here (Claude's discretion, recorded)

- A request is a joiner row with join_path request; the worker declines it like it bans a joiner (paced, retried, three attempts). A new request from someone with a finished row is reclaimed at once, with no 20 s window, because Telegram delivers each request once.
- The request path fails closed: a failed lockdown read or row write ends handling, so a request stays pending (harmless) instead of reaching auto-approve. The join paths fail open, because a joiner is still muted by the locked default.
- The Accept button checks the lockdown fresh; a failed read is treated as locked (no approval).
- /antiraid keeps working until Phase 6 (LOCK-15); during a lockdown its join handler returns at once, so it neither temp-bans an admin-added user nor counts joins toward its auto-trigger.

## Assumptions recorded

- A11 (research): a declined person can request again at once; each new request is declined again under the pacer. No per-user suppression is planned (research Open Question 6, revisited in Phase 6).
