## Phase Goal

**As a** group admin, **I want to** manage my group from one button menu, **so that** staff, lockdown, captcha and antiflood need no commands.

**This slice:** an admin opens the menu in the group, changes the captcha time limit with two taps, and the command shows the same value.

## Decisions taken here (Claude's discretion, recorded)

- Apply functions live beside the command they were extracted from (`captcha.go`, and in later plans `antiflood.go`, `autolockdown.go`, `lockdown.go`), not in a separate `settings_apply.go`: the command body and its apply function stay in one file, and no shared file is edited by two plans of one wave. Each domain has its own small typed result (here `captchaApplyResult`); there is no shared status enum.
- Callback fields (UI-SPEC "Callback data"): `a` action, `c` group chat ID (private menu), `u` opener user ID (group menu), `p` page (`s` staff, `l` lockdown, `c` captcha, `f` antiflood), `t` control, `v` absolute target value, `e` confirm expiry (unix minutes, plan 09-11), `s` Staff Group row ID (plan 09-11). Core action codes here: `oh` open here, `op` open page `p` (also Refresh and a stepper's value button), `bk` Back to Main, `cl` Close, `tg` toggle, `st` set, `no` cancel a card back to page `p`. Page-specific codes (`ls`, `ly`, `ua`, `uy`, `lk`, `pg`) are declared by the page that owns them through `registerSettingsPage`, which panics at init on a duplicate page key or action code.
- Page registry: every page file registers itself from its own `init()` with `registerSettingsPage(settingsPage{...})`, so a new page is one table entry plus its strings and never edits `settings_pages.go` (D-16). Order values: Staff Group 10, Lockdown 20, Captcha 30, Antiflood 40.
- `settingsPage` fields: `Key` (the `p` value), `Order`, `Icon`, `TitleKey` (a literal locale key), `MainState func(b *gotgbot.Bot, tr *i18n.Translator, group *gotgbot.Chat) (state string, ok bool)` (no press, so the private entry of plan 09-07 can draw the same Main page without one; database reads only, no Telegram call), `Open func(p *settingsPress, notice string) (settingsScreen, error)` (an error is the D-11 cannot-open edit), `Controls map[string]settingsControl` (by `t`, for `tg` and `st`) and `Actions map[string]settingsPageAction`. `settingsControl` is `{Right settingsRight; Set func(p *settingsPress, value string) *settingsScreen}`; `settingsPageAction` is `{Fields []string; Right settingsRight; Run func(p *settingsPress) *settingsScreen}`. A nil screen means the handler already answered (a bound toast) and nothing is edited.
- Answer order: `settingsPress.answer(text, alert)` sends at most one `answerCallbackQuery` (an `answered` flag), and the dispatcher answers empty after a handler that did not answer. A handler that does slow work (captcha off cleanup, the Staff page build, a lift) answers empty itself before it starts (D-31); a refusal found later is a notice line on the redrawn page.
- Rights are a pure function of the press: `settingsRightRefusal(p *settingsPress, right settingsRight) (key string, alert bool)` returns `""` when allowed. The bot-admin rights use the commands' own cached predicates (`chat_status.IsBotAdmin(b, nil, group)` for `/captcha`, `chat_status.IsUserAdmin(b, group.Id, b.Id)` for antiflood), never a live `FetchBotMember`, so the menu refuses exactly what the command refuses (research Pattern 4).
- Steppers send absolute targets computed at render time. `settingsStepperRow` takes the current value, the step list (`-1, +1` for the time limit; later `-10, -1, +1, +10`), a clamp function and the value label; a target equal to the current value (only possible at a bound) is labelled `·` and keeps valid data. A `st` press whose target equals the stored value at a bound answers the toast `settings_min_value` / `settings_max_value`; any other in-range target is written.
- Text layout (UI-SPEC "Message Layout"): `settingsCompose(view, titleKey, body []string, notice string, updated bool)` writes the header (`settings_header_main` when `titleKey` is empty, else `settings_header` with `{page}`), the group line `<b>{staffDisplayTitle(title)}</b> <code>{id}</code>`, one blank line, the body lines, and when present one blank line and the footer (the notice line first, then `staff_panel_updated` when `updated`). Notices are `⚠️ ` + text for refusals and `✅ ` + text for successes. Icons are code constants.
- `settingsDesc` reuses `requireLockdownGroup()` and `requireLockdownAuthority(false)` (D-29): live creator or administrator, anonymous admin sent to the proof, refusals as replies. The choice message has no Close button (D-01 lists two buttons).
- Seams for tests: `var settingsCaptchaRead = captcha.GetCaptchaSettingsContext` in `settings_captcha.go`, reassigned only by tests (pattern `raidSettingsLookup`).
- Environment: golangci-lint cannot lint Go 1.26 here, so `go vet -tags testtools` and `gofmt -l` stand in for `make lint`; the orchestrator runs `make test` after the wave.
