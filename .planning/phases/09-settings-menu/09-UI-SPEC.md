# Phase 9 - UI Design Contract

> Visual and interaction contract for the Telegram settings menu: the `/settings` choice message, the one-message
> button menu (Main, Staff Group, Lockdown, Captcha, Antiflood), its confirm cards, alerts and the private entry.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Upstream: 09-CONTEXT.md D-01..D-19 (locked, not reopened), REQUIREMENTS MENU-01..MENU-08, AGENTS.md (Callbacks,
> Permissions, Data), the Phase 8 contract (locale-key table format), and the code of `staff_panel.go`,
> `lockdown_alert*.go`, `autolockdown.go`, `captcha.go`, `antiflood.go`, `help.go`.

This phase has no web screen. Everything is a Telegram message in HTML parse mode plus an inline keyboard.
Template sections that assume CSS, fonts, pixels or colour are replaced by their Telegram equivalent
(message layout, text styling, status icons, keyboard layout). Nothing here adds a setting: every control
calls the apply function its command uses (D-17).

Items that conflict with the code or with an earlier phase are NOT applied silently; they are listed in
"Amendments proposed" at the end. Where an amendment changes a screen, the screen below follows CONTEXT as
written and says "see A-n".

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Telegram Bot API, gotgbot v2) |
| Preset | not applicable |
| Component library | none: `gotgbot.InlineKeyboardMarkup` rows of `InlineKeyboardButton` |
| Icon library | Unicode emoji only, not localized (same practice as `staffStatusIcon`); every word around them is a locale key |
| Font | none: Telegram client fonts. Styling is limited to the HTML tags in "Text Styling" |

Project scan: no `components.json`, `tailwind.config.*`, `package.json`, `.tsx` or `.css` in the repo (same as
Phase 8). Existing Telegram UI matched in style and wording: the `/staff` panel (`renderStaffPanel`,
`composeStaffPanelText`, `staffRowStatuses`), the lockdown alert and its two-tap cards (`lockdown_alert_*`),
`/lockdownstatus` (`lockdown_status_*`), `/autolockdown` (`lockdown_auto_*`), the captcha settings reply
(`captcha_settings_*`) and the antiflood replies.

Component Inventory: omitted (`Tool: none`).

Telegram limits this contract is built inside:

| Limit | Value | Where it bites |
|-------|-------|----------------|
| Message text | 4096 characters after parsing; the bot caps its own HTML at 3800 UTF-16 units (`staffPanelMaxUTF16`) | only the Staff Group page opened inside a Staff Group can approach it; every page is held to the cap by a test |
| Callback data | 64 bytes, through `alita/utils/callbackcodec` only, namespace `settings` (`settings\|v1\|...`) | table "Callback data" below, worst case 53 bytes |
| Buttons | at most 8 per row, 100 per message | widest row used is 5; most buttons on one page is 21 (Lockdown) |
| `answerCallbackQuery` alert text | 200 characters, plain text (no HTML) | every key used as an alert is held to 120 EN / 170 other |
| Button label | no hard limit, but clients cut it with an ellipsis at roughly 20 visible characters on a 3-per-row line, about 40 on a full-width row | ceilings per key in the locale table |

## Message Layout (replaces Spacing Scale)

Telegram has no pixel spacing. Spacing is blank lines, line breaks and keyboard rows.

Every page message has this anatomy (one render pipeline for all pages, D-16):

```
<header line>                      settings_header_main, or settings_header with the page name
<b>{group title}</b> <code>{group chat id}</code>
<blank line>
<body lines>                       page specific, one fact per line
<blank line>
<footer line(s)>                   optional: notice, hint, "Updated HH:MM:SS UTC"
```

| Rule | Contract |
|------|----------|
| Header | line 1, never omitted, never wrapped: `⚙️ <b>Settings</b>` on Main, `⚙️ <b>Settings</b> · {page}` elsewhere |
| Group line | line 2 on every page and every card: the group's title (`staffDisplayTitle`: cut at 64 runes, then `html.EscapeString`) in `<b>`, one space, the chat ID in `<code>`. This is how a private menu shows which group it manages |
| Blank lines | exactly one blank line between header block, body and footer. No two blank lines anywhere. Between body facts, a single newline |
| Notice line | an action's result or refusal (see "Notices and alerts") is the first footer line, prefixed with a status icon, and is dropped on the next redraw |
| Updated line | Staff Group and Lockdown pages end with `staff_panel_updated` ("Updated 14:05:09 UTC"), because those pages read live state another admin can change. Captcha and Antiflood pages do not |
| Length | every rendered page is at most 3800 UTF-16 units. Free-text values are cut before rendering: group title 64 runes, a person's name 64 runes, a lockdown reason 200 runes followed by "…" (`settings_lockdown_reason` prints the cut value). A test renders the worst case in all 7 locales |
| Keyboard order | content rows first, then the single navigation row: `[ Back | Close ]` on every sub-page and every card, `[ Close ]` alone on Main. The navigation row is always the last row, Back always left, Close always right (D-06) |
| Row width | choice rows hold 3 buttons, steppers hold 5 (or 3 for the captcha time), pairs hold 2, everything else is one button on its own row |
| Touch | no button is empty; every button either carries valid callback data or is not rendered (see "Callback data") |

## Text Styling (replaces Typography)

| Role | Telegram markup | Used for |
|------|-----------------|----------|
| Page header | `<b>` on the word "Settings" only | line 1 |
| Value | `<b>` | the current value of a control on its text line (`Mode: <b>Math</b>`) |
| ID | `<code>` | chat IDs only (group, Staff Group). Never user IDs, never values |
| Section label | `<b>` on its own line | "Automatic triggers" on the Lockdown page |
| Plain | none | everything else |

No `<i>`, `<u>`, `<pre>`, no links, no custom emoji. Only `<b>` and `<code>` are used, so a translator has two tags to
keep. User-controlled strings (group titles, staff group titles, names, reasons) are escaped and spliced in AFTER
translation through a token, never passed through the translator's printf pass (pattern: `lockdownGroupToken`,
`staffGroupTitleToken`). Button labels are plain text: no HTML, titles cut at 20 runes (`staffButtonTitle`).

Parameters in new keys use the brace style of the newer keys (`{group}`, `{n}`, `{state}`), matching `staff_*` and
`lockdown_*`.

## Status Icons (replaces Color)

No colours exist. State is carried by icon plus word, never by icon alone. Icons are code constants.

| Meaning | Icon | Used for |
|---------|------|----------|
| on, yes, healthy | ✅ | trigger/captcha/delete switches that are on, selected choice, health row (reuse `staffStatusIcon`) |
| off, no, unhealthy | ❌ | switches that are off, health row (reuse) |
| could not be checked | ❔ | health row, a main-page state whose read failed (reuse) |
| lockdown active | 🔒 | Lockdown page status line, main-page button, `staff_panel_row_lockdown` |
| lockdown lifted / none | 🔓 | "not in lockdown" line, Lift button |
| warning, refusal notice | ⚠️ | the notice line when something was refused or not saved |
| success notice | ✅ | the notice line after a link, unlink or lift |
| page icons | 👥 Staff Group, 🔒 Lockdown, 🧩 Captcha, 🌊 Antiflood | main-page buttons only |
| controls | ⚙️ header, 🔄 Refresh, ⬅️ Back, ✖️ Close, ➕ Link, ➖ Unlink, 💬 Open here, 📩 Open in private | as named |

Selected-choice convention (mode, failure action, antiflood action): the selected button's label is `✅ ` plus the
word; unselected buttons show the word alone. Toggle convention: the label shows the CURRENT state, never the
action (`Captcha: ✅ On`), and pressing flips it. Stepper convention: the middle button shows the current value and
pressing it redraws the page (it is also the page's refresh, so it goes through the full live check, MENU-03).

## Interaction Contract

### Ownership and language

| Menu opened | Buttons carry | Responds to | Language |
|-------------|---------------|-------------|----------|
| In the group (`/settings` then "Open here") | `u` = the opener's user ID; the group is the chat the message sits in | only that user (D-02) | the group's language |
| In private (deep link `?start=settings_<chat id>`) | `c` = the group's chat ID; no opener field | the user the private chat belongs to | the admin's own language |

A callback is refused as "Invalid request" (`common_callback_invalid_request`, alert) when: the data does not decode;
it carries neither or both of `c` and `u`; `c` is present but the message is not in a private chat; `u` is present but
the message is in a private chat; `c` or `u` is not a plain integer inside the same bounds other chat IDs use; the
action code is unknown. The message being inaccessible answers `common_callback_message_unavailable`.

### Press pipeline (every `settings|v1` callback, in this order, each step refusing before the next runs)

1. Decode and structural checks above. No I/O.
2. A Telegram service identity (`staffServiceUserIDs`) is answered `lockdown_alert_post_as_yourself` (alert), before any lookup.
3. Group menu only: `query.From.Id` must equal `u`, else `settings_not_your_menu` (alert), nothing else runs.
4. Live `getChatMember` of the presser in the group being configured (the callback's `c` in private, the message's chat
   in a group): creator or administrator. A failed lookup refuses with `settings_check_failed` (alert); a non-admin,
   including a demoted opener, gets `settings_not_admin` (alert). Never the admin cache (D-04). Nothing is edited.
5. Per-action right (table "Authority per control"), live again, at the ask AND at Confirm. Refusal: alert for the short
   new keys, notice line for reused command texts (rule below).
6. The action runs through its apply function. A refusal the apply function returns is rendered, not swallowed.
7. The callback is answered exactly once (empty for a normal success), then the same message is edited in place with the
   redrawn page. `message is not modified` is success (`isMessageNotModified`). A 429 on the edit is not retried: the
   change is already saved and the next press redraws. A failed edit never undoes a write.

Exception to the answer order: the Staff Group page opened inside a Staff Group (`buildStaffPanelRows` makes up to
2N+1 live calls) answers empty first, then builds and edits, exactly as `staffPanelRebuild` does.

The page after a write is drawn from the apply function's returned value merged into the snapshot, not from a re-read,
so another replica's 10 s in-process cache can never show the old value right after the change (D-18). Every later
redraw reads through the same cached getters the commands use.

### Notices and alerts (where a refusal is shown)

| Kind | Shown as | Rule |
|------|----------|------|
| New short refusals made for the menu (`settings_not_your_menu`, `settings_not_admin`, `settings_no_restrict`, `settings_check_failed`, bounds) | alert (`show_alert=true`), plain text, at most 200 characters | the page is not edited |
| Reused command texts (Staff link/unlink refusals, Turnstile refusals, lockdown lift results, `chat_status_bot_not_admin`) | notice line on the redrawn page, `⚠️ ` plus the text (HTML) | some contain `<code>`, a group title or exceed 200 characters in other languages (Phase 8 allowed 224), so they can never be an alert. The callback is answered empty |
| Expired confirm | notice line `settings_card_expired`, page redrawn without the card | nothing was changed |
| Success of link, unlink, lift | notice line with `✅ ` | other successes (toggle, stepper, choice) show only the new value, no notice |
| Menu cannot render | alert `settings_cannot_open_alert` plus the message edited to `settings_cannot_open`, no keyboard (D-11) | "group no longer exists", "bot was removed", a failed fresh read of the page's own data |

### Entry: `/settings` in a group (MENU-01, D-01)

`helpers.WrapCommand`, admin check, group only, not `Disableable`; anonymous admins get the usual proof and re-enter
through `RegisterAnonymousAdminHandler` (the tapper becomes the opener). The reply goes to the command message.

```
⚙️ Settings
Where do you want to open the settings for Fuku Test Group?

[ 💬 Open here | 📩 Open in private ]
```

- Open here: callback `a=oh&u=<opener>`. Runs steps 1-5, then edits THIS message into the Main page (the choice message
  becomes the menu; no second message).
- Open in private: a `url` button, `https://t.me/<bot username>?start=settings_<chat id>` (payload `settings_-1001234567890`,
  23 characters of `[A-Za-z0-9_-]`, inside Telegram's 64). It is not callback data, so the 64-byte cap does not apply.
  Anyone can tap a URL button; authority is decided only when `/start` arrives.
- No Close on the choice message (D-01 lists two buttons). It stays until used; an auto-close is deferred.

### Entry: `/start settings_<id>` in private (MENU-01, D-03)

One payload branch in `start`'s private two-argument path. The payload must match `settings_` plus digits with an optional
leading minus and the same bounds as other chat IDs, else the user gets `settings_start_invalid` (plain reply, no menu).
Then, in this order: the live admin check of that user in that group (`getChatMember`), a refusal replies
`settings_start_not_admin` (plain reply, no menu; a failed lookup replies `settings_check_failed`); the group lookup (bot
not in the group, group gone) replies `settings_cannot_open`; otherwise the Main page is sent to the private chat in the
admin's language. All other `/start` behaviour is unchanged.

### Close (D-06)

Press Close: steps 1-4, then delete the menu message. If the delete fails (private message older than 48 h, missing
right) edit the message to `settings_closed` with no keyboard. Answer once, empty.

### Back

Back always redraws the Main page (the menu is two levels deep). Cancel/No on a confirm card returns to the page that
asked, not to Main.

### Steppers

All steppers send an ABSOLUTE target value, computed when the page was rendered (`v`), never a delta. A double tap is
therefore idempotent and a lost update is bounded to the stale page's value. The handler re-validates the range through
the same apply function the command uses (D-19 drift test), so a forged `v` is refused with the command's own range
text as a notice.

| Stepper | Range | Buttons | Notes |
|---------|-------|---------|-------|
| Join surge / Flood / AI spam threshold | 3..500 (`raiddetection.MinThreshold/MaxThreshold`) | `−10`, `−1`, value, `+1`, `+10` | a threshold write also turns the trigger on (command rule, D-13); the toggle label then shows On |
| Antiflood limit | Off, 3..100 (`/setflood`: `3..100`, `off`/`0` disables) | `−10`, `−1`, value ("Off" or the number), `+1`, `+10` | Off sits below 3. From 3, `−1` and `−10` give Off. From Off, `+1` gives 3 and `+10` gives 12. The lowest and highest stops are described below |
| Captcha time limit | 1..10 minutes | `−1`, value (`2 min`), `+1` | 3 buttons |

At a bound the unusable step buttons are labelled `·` (a middle dot) and keep valid callback data. Pressing one answers a
toast alert `settings_min_value` / `settings_max_value` with the bound and changes nothing. A step that would cross a bound
(for example `+10` from 495) lands exactly on the bound instead of being refused.

### Two-tap confirm cards (D-09)

Lift lockdown and Unlink. The card replaces the page text in the same message; the page's keyboard is replaced by
`[ ✅ Yes | ❌ No ]` plus the navigation row. Yes carries the expiry `e` (unix minutes, now + 5 minutes,
`settingsCardLifetime`); expiry is lazy, no timer, no Redis key. A Yes whose `e` is before the current unix minute redraws
the page with `settings_card_expired` and runs nothing. A Yes re-runs steps 1-5 live. Group menu: only the opener can
press anyway (step 3). A card never outlives its message and works without Redis.

```
⚙️ Settings · Lockdown
Fuku Test Group  -1001234567890

Lift the lockdown in Fuku Test Group? Its permissions go back to what they were before, and the people removed during
the lockdown are unbanned, except accounts banned for good with Ban recent joiners, which stay banned.

[ ✅ Yes | ❌ No ]
[ ⬅️ Back | ✖️ Close ]
```

The Unlink card uses `staff_unlink_confirm_prompt` ("Are you sure you want to unlink {group}? Staff commands will no
longer reach it.") with the same two rows.

### Authority per control (D-05; the menu never does more than the command)

| Control | Needs (live, at the ask and at Confirm) | Refusal shown |
|---------|----------------------------------------|---------------|
| Open the menu, view any page | creator or administrator of the group | `settings_not_admin` / `settings_check_failed` (alert) |
| Lift lockdown (ask and Yes) | creator, or administrator with `can_restrict_members` (`lockdownButtonAuthority` rule) | `settings_no_restrict` (alert); not an admin: `settings_not_admin` |
| Lockdown trigger switch and threshold | same as Lift (`requireAutoLockdownAuthority`, change branch) | same as Lift |
| Staff Group Link | live creator of this group and of the chosen Staff Group (`runLinkGroup`'s checks) | the command's refusal text through `staffLinkRefusalText`, as a notice |
| Staff Group Unlink (ask and Yes) | live creator of this group and of its Staff Group (`/unlinkstaff`'s checks) | `staff_unlink_refuse_*` / `staff_unlink_not_linked`, as a notice |
| Captcha on/off | admin AND the bot an admin (`captchaAdminGate(..., true)`) | `chat_status_bot_not_admin`, as a notice |
| Captcha mode, time limit, failure action | admin (`captchaAdminGate(..., false)`) | alerts above |
| Captcha mode Turnstile | the three ordered refusals of `captchaWebModeRefusal` (not set up, no Redis `PING`, bot lacks Restrict) | `captcha_web_refuse_*`, as a notice; nothing is written |
| Antiflood limit, action, delete switch | admin (what `/setflood`, `/setfloodmode`, `/delflood` check) | alerts above |

A control the presser lacks the right for is still drawn (hiding it would make the page differ by person and hide why);
the press is refused.

## Pages

Mock values: group "Fuku Test Group" `-1001234567890`, Staff Group "Fuku Staff" `-1001111111111`, opener "Alex".
`[ a | b ]` is one keyboard row. Every page ends with the navigation row.

### Main

```
⚙️ Settings
Fuku Test Group  -1001234567890

Pick what to manage. A change made here is the same as the matching command.
Only Alex can use this menu.                     <- group menu only

[ 👥 Staff Group · Linked ]
[ 🔒 Lockdown · Not active ]
[ 🧩 Captcha · On ]
[ 🌊 Antiflood · Limit 5 ]
[ ✖️ Close ]
```

Button label = page icon + page name + ` · ` + state. States: Staff Group: `Linked`, `Not linked`, or `{count} linked`
when this group is itself a Staff Group; Lockdown: `Not active`, `Active`, `Lifting`; Captcha: `On` / `Off`
(`common_status_on/off`); Antiflood: `Limit {n}` or `Off`. A read that fails leaves the state out and appends ` · ❔`.
The loader makes four reads (staff link fresh, lockdown fresh, captcha cached, antiflood cached) and no Telegram call.
The "Only {name} can use this menu." line is shown in a group menu, with the opener's name escaped after translation.

### Staff Group - in a linked group (D-12, MENU-05)

Linked:

```
⚙️ Settings · Staff Group
Fuku Test Group  -1001234567890

Linked to: Fuku Staff  -1001111111111
Bot is admin: ✅ | Can restrict members: ✅ | Owner matches: ✅
🔒 In lockdown since 30 Oct 14:02
✅ yes | ❌ no | ❔ could not be checked

Updated 14:05:09 UTC

[ 🔄 Refresh | ➖ Unlink ]
[ ⬅️ Back | ✖️ Close ]
```

A broken row adds the `staff_panel_reason_*` line under the status row, exactly like `renderStaffRow`; the lockdown
line appears only while a lockdown is confirmed (`staff_panel_row_lockdown`). Health comes from one
`buildStaffPanelRows` call for this one link (at most 3 live Telegram calls). See A-2 for the Staff Group name and ID in
a menu opened in the group.

Not linked:

```
⚙️ Settings · Staff Group
Fuku Test Group  -1001234567890

This group is not linked to a Staff Group.
Only the creator of this group who also created a Staff Group can link it.

[ ➕ Link to a Staff Group ]
[ ⬅️ Back | ✖️ Close ]
```

Link press: `resolveOwnStaffGroup` decides. Exactly one verified Staff Group: link at once through `runLinkGroup`'s code
(including its post to the Staff Group, nothing posted into the linked group) and redraw with notice
`✅ This group is now linked to your Staff Group.` None: notice with `staff_link_no_staff_group`. More than one: the
picker (A-3):

```
⚙️ Settings · Staff Group
Fuku Test Group  -1001234567890

Which Staff Group should this group join?

[ 👥 Fuku Staff ]
[ 👥 Fuku Staff 2 ]
[ ⬅️ Back | ✖️ Close ]
```

One button per Staff Group the user owns (`ListStaffGroupsByOwner`, at most 8 shown, label `👥 ` plus the title cut at 20 runes,
callback `a=lk&s=<staff chat id>`). A pick is verified live again by `resolveNamedStaffGroup`; a refusal is a notice.

Unlink press: `[ ➖ Unlink ]` opens the Unlink card; Yes runs `/unlinkstaff`'s code, redraws as "Not linked" with notice
`✅ This group is no longer linked to a Staff Group.`

```
Fuku Staff  -1001111111111

Staff Group chat ID: -1001111111111
Linked groups (2):
Page 1/1                                         <- only when more than one page

Fuku Test Group 1234567890
Bot is admin: ✅ | Can restrict members: ✅ | Owner matches: ✅

Fuku Test Group 2 987654321
Bot is admin: ✅ | Can restrict members: ❌ | Owner matches: ✅

🔒 In lockdown since 30 Oct 14:02

✅ yes | ❌ no | ❔ could not be checked
Updated 14:05:09 UTC

This is a Staff Group. Link or unlink a group from that group's own settings menu.

[ ⬅️ Prev | Next ➡️ ]                              <- only with more than one page (8 groups per page)
```

Not in lockdown (supergroup):

Active (confirmed). The status line is `lockdown_status_active` (manual, with the starter's name) or
`lockdown_status_active_auto` (automatic, trigger sentence), exactly as `/lockdownstatus` words it, followed by

```
🔒 In lockdown since 30 Oct 13:40, started by Sam.

Automatic triggers ... (same block)

[ 🔓 Lift lockdown ]
[ trigger rows as above ]
[ ⬅️ Back | ✖️ Close ]
```

Read failure: body `I couldn't read the lockdown state right now. Press Refresh to try again.` and the keyboard is
`[ 🔄 Refresh ]` plus navigation; no trigger rows (their values are unknown).

the `autolockdown` rules (a threshold also turns its trigger on). Lift `a=ls`, Yes `a=ly&e=..`, which calls
`liftLockdownRow` exactly as `/unlockdown` does and shows the lift result with the lockdown module's own texts as a
notice: `lockdown_lifted`, `lockdown_already_lifted`, `lockdown_lift_in_progress`, `lockdown_lift_record_failed` or
`lockdown_not_active`. The lockdown is read fresh at the ask and again at Yes; a lockdown that is no longer active at
the ask redraws the page with `lockdown_already_lifted`/`lockdown_not_active` instead of a card.

### Captcha (D-14, MENU-07)

```
⚙️ Settings · Captcha
Fuku Test Group  -1001234567890

Captcha: ✅ On
Mode: Math (mathematical problems)
Time limit: 2 min
If not solved: Kick

[ Captcha: ✅ On ]
[ ✅ Math | Text | Turnstile ]
[ −1 | 2 min | +1 ]
[ ✅ Kick | Ban | Mute ]
[ ⬅️ Back | ✖️ Close ]
```

- Mode description reuses `captcha_mode_math_desc`, `captcha_mode_text_desc`, `captcha_mode_turnstile_desc`; failure action words
  are `settings_opt_kick/ban/mute`.
- Presses: toggle `a=tg&t=e&v=0|1`; mode `a=st&t=m&v=math|text|turnstile`; time `a=st&t=t&v=1..10`; action
  `a=st&t=f&v=kick|ban|mute`. They call the apply code of `/captcha`, `/captchamode`, `/captchatime`, `/captchaaction`.
- Turnstile availability. The page renders without I/O, so it can only know the first refusal. When the web captcha
  is not configured (`CaptchaWebConfigured()` false or no bot username) the Turnstile button is labelled `🚫 Turnstile` and
  pressing it shows the refusal `captcha_web_refuse_not_configured` as a notice. When it is configured the button looks
  normal, and the other two refusals (no Redis within 250 ms, bot lacks Restrict) are found at the press, in the
  command's order, as a notice. If the STORED mode is `turnstile` while the web captcha is unavailable, a line
  `settings_captcha_fallback_note` is added under the mode line (new members get the math captcha, D-09 of Phase 8).
- Max attempts is not in the menu (D-14); `/captchamaxattempts` stays a command.

  `This action cannot be set from the menu. Pick one of the buttons below to replace it.` and NO button in the choice

## Callback data (64-byte cap)

Namespace `settings`, version `v1`, built only with `encodeCallbackData` / `callbackcodec.Encode`, read only with
`decodeCallbackData` (never `strings.Split`). The encoder sorts fields by key and URL-encodes values; `-` is unreserved so a
negative chat ID is not expanded. Prefix `settings|v1|` is 12 bytes.

| Field | Meaning | Values | Bytes (key, `=`, value) |
|-------|---------|--------|-------------------------|
| `a` | action | 2-letter code, table below | 4 |
| `c` | group chat ID (private menu) | up to 14 characters with the sign | 16 |
| `u` | opener user ID (group menu) | up to 10 digits | 12 |
| `p` | page | `s` staff, `l` lockdown, `c` captcha, `f` antiflood | 3 |
| `t` | control | Lockdown: `j` join surge, `f` flood, `a` AI. Captcha: `e` enabled, `m` mode, `t` time, `f` failure action. Antiflood: `l` limit, `m` action, `d` delete | 3 |
| `v` | target value | `0`/`1`, a number up to 3 digits, or `math` `text` `turnstile` `kick` `ban` `mute` | 3 to 11 |
| `e` | confirm expiry, unix minutes | 8 digits until the year 2160 | 10 |
| `s` | Staff Group chat ID (Link pick) | up to 14 characters with the sign | 16 |

Action codes: `oh` open here (choice message), `op` open page `p` (also Refresh and a stepper's value button), `bk` Back,
`cl` Close, `tg` toggle, `st` set a value, `ls` Lift ask, `ly` Lift Yes, `ua` Unlink ask, `uy` Unlink Yes, `lk` Link (with
`s` for a pick), `no` cancel a card (back to page `p`), `pg` Staff panel page.

Worst case per button, with `c` = `-1001234567890` (14 characters) and `u` = `1234567890` (10 digits), `e` = `29800000`:

|--------|------------------------|---------------|-------------|

every page for the worst-case IDs and fails if any button was omitted, so a dead button can never ship (D-07). A stepper
button whose target equals the current value at a bound is NOT omitted (it keeps data and answers the bound toast).

## Amendments proposed

CONTEXT is treated as locked. The following came out of reading the code and earlier phases. None is applied in this
contract unless stated; each says what changes if accepted.

**A-1. Antiflood actions (D-15).** CONTEXT lists "mute, ban, kick, warn" as selectable and `tban`/`tmute` as command-only
because they need a duration. In the code, `/setfloodmode` accepts only `ban`, `kick`, `mute` (`antiflood.go`, `setFloodMode`),
nothing writes `warn`, `tban` or `tmute` to `antiflood_settings`, and no command takes a duration for antiflood. Making `warn`
selectable would change `/setfloodmode`'s accepted words (D-17 forbids changing observable replies). This contract therefore
offers mute, ban and kick, and shows a stored `warn`, `tban` or `tmute` as the current value without a selected button.
It never says a command can set them. The limit range is also the command's: Off, then 3..100 (not "any number").
If accepted: D-15 reads "mute, ban, kick; other stored values are shown read-only".

**A-2. The Staff Group page in a menu opened in the group (D-12) reveals the link to every member.** A group menu is an
ordinary group message. Showing "Linked to: <Staff Group title and ID>" and the bot's health there tells all members that
the group is linked and to what, while Phase 1 (D-06) says nothing about a link is ever shown to the linked group's
members, and `/linkstaff` deletes its own command message for the same reason. The Main-page state label (`Linked`) and the
unlink/link notices have the same effect. As written, this contract follows D-12 literally for the private menu and the
group menu alike. Proposed: in a menu opened in the group, replace the "Linked to" line with `settings_staff_linked_hidden`
("Linked to a Staff Group."), omit the Staff Group's ID and title, and keep the health, owner and lockdown rows (they reveal
nothing about the Staff Group); the full line stays in the private menu. Decision needed before planning.

**A-3. A Link picker is needed (D-12 gap).** `/linkstaff` takes an optional Staff Group chat ID because an owner can have
several Staff Groups (`resolveOwnStaffGroup` refuses "need a Staff Group ID" when more than one matches). D-08 allows no
free-text input, so the menu needs a stateless picker: one button per Staff Group the user owns, data `a=lk&s=<staff chat id>`,
re-verified live by `resolveNamedStaffGroup`. No new setting and no new state. Adds action `lk` with field `s` and the key
`settings_staff_pick`. Included in this contract; flagged because it is more than D-12 states.

**A-4. Reused keys (D-10).** D-10 says all strings are new `settings_*` keys. Reusing the existing `staff_*`, `lockdown_*`,
`captcha_*` and `chat_status_*` texts is what makes "where a command refuses, the menu refuses with the same words"
(Specifics, D-05) true without duplicating 7-language translations that could drift. This contract reuses them (table above)
and adds `settings_*` keys only for new menu text. If the owner wants every string new, the reused rows become copies and the
drift risk is accepted.

**A-5. The value button is a refresh.** CONTEXT leaves the stepper's value button open. It is `a=op` (redraw this page), so
it needs no special no-op path and every press still runs the live check of MENU-03. Not a conflict; stated for the planner.
