After this plan the message check is complete and proven behind one switch: once 13-13 turns it on, every member is checked when they send a message, a violator is punished once with one notice whatever replica sees their messages, and a clean member costs no Telegram call.

- Group -2 holds only the admin cache's `my_chat_member` handler today (`bot_updates.go:273-275`), so for a message the watcher is alone in its group; AGENTS.md gains the rule that no other message handler may be added to group -2 (research S-01).
- The switch is a plain package variable read once per update (no lock: it is written only at init and by tests before they send updates, and `go test -race` runs every test that sets it through `withMemberReqLive`). It is the property "no commit before the last of the join plan and the button plan can punish a member in a real group" made into code.
- The pass value is read and written through the operational Redis client of the raid counters (`raidRedis()`, nil without Redis) under `raidRedisTimeout`; a Redis error or no Redis is a miss, and the clean predicate then runs on every message (correct, slower).
- `memberReqJobTimeout` is 2 minutes: a job makes at most four paced calls, each of which may wait up to the pacer's 60 s `MaxWait` for a slot before failing as rate limited.
- The watcher uses `cachedAdminStatus` only to skip a job for a known admin; an unknown cache goes to the job, whose live `getChatMember` decides (research Open Question 15).
- A basic group is not screened in this phase (D-20): mute and kick are supergroup methods. The page gets no line for it (a new hint key would break the UI contract's 36-key budget); AGENTS.md records it as a documented limit and 13-14 lists it in 13-SPIKE.md; Phase 14's "cannot work here" line (MREQ-10) is where the page says it.
- Test hygiene: as 13-07 (`memberReqEnv`, `mreqMember` IDs, `memberReqCleanup`); the replicas share the env's database and miniredis, so the cleanup also deletes the pass keys of its chats; tests that call `StopMemberReqJobs` restore the runner with `restoreMemberReqRunner`; every test that turns the switch on does so through `withMemberReqLive`.
