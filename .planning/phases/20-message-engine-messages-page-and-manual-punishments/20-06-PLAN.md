## Phase Goal

**As a** group owner, **I want** to set what the bot says in a group when an admin bans, kicks, mutes, unbans or unmutes someone, from that group's settings in the bot's private chat, **so that** the replies sound like my community, while a group that sets nothing sees no change.

After this plan the owner sees, in the group's private settings, a Messages page that lists the seven manual events with their states and opens each event's screen.

<objective>
Register the private-only Messages page (MSG-05, D-18, D-19): its table of families and events, the hub (every family with events, each event's state), the family list, the event screen (the parts' states), the Main state, the group-menu note (a new optional `PrivateNoteKey` of the framework), the Staff Group `Hidden`, and one message editor definition per event through plan 20-03's registry. Add the page's strings in all 8 languages and update the registry-iterating tests and AGENTS.md.

Screens (fixed here; later plans add rows to the event screen only):
- Hub (`a=op&p=h`): header `settings_page_msgs`, the group line, `settings_msg_intro`, then for each family with events a blank line, `<icon> <b><name></b>` and one `settings_main_state_line` per event (event icon, event name, its state word). Keyboard: one cell per family with events, two to a row, an odd last one alone (`a=hl&t=<family>`), then Back (Main) and Close. Rows today: `[1] [2]`.
- Family list (`a=hl&t=m`): `settings_msg_fam_manual_intro`, a blank line, the seven event state lines, a blank line, `settings_msg_list_hint`. Keyboard: one cell per event (`<icon> <name>`, `a=he&k=<code>`), two to a row, then Back (`a=op&p=h`) and Close. Rows: `[2 2 2 1 2]`.

- Group menu: Main's line is `settings_state_private_only`; opening the page is `settings_msg_group_note` with the Open in private row, then Back and Close.

## Planner assumptions and decisions (flagged)

- Page key `h` is unused by every registered page and every test (`q` is used in tests as an unregistered key, so it was avoided). `Order` 74 puts Messages right after Reactions (73), the group of message pages, before Member requirements (80). The action codes `hl he hs hr hc hv hf hq` are unused (no settings action code starts with `h`). The event field is `k`, not `e`, because `e` is the confirm-card expiry everywhere else in the namespace.
- Main grows to 21 cells for a group that is not a Staff Group: `s|l / c|f / n|k / b|i / w|g / r|e / x|h / m|d / t|u / z|o / y`, then Access for the owner and the navigation row: 13 rows for the owner and 12 for an administrator, private and group alike. The Staff Group's Main is unchanged (the page is Hidden there, D-01: nothing is set at Staff Group level), so `settings_fwdblock_test.go`'s Staff Group shapes are not edited; `TestSettingsPhase18InStaffGroup`'s count becomes `len(settingsMainTitleKeys)-1` because the title list gains Messages, which a Staff Group does not show.
- `settingsMsgHidden` is true only for a definite Staff Group row read fresh through `deletionStaffLookup` (the Deletion page's seam); an unreadable row shows the page, which only edits messages a Staff Group never posts.
- The page reads through `eventmsg.GetFresh` (the page is not the hot path; a fresh read never shows a value another replica just changed as stale) and creates nothing. Main's count is the number of events whose state is not Default (Custom or Silent).
- Every page action requires the private owner field `c` (`settingsListPrivateField`), so a forged press of a group menu is refused in step 1, before any `getChatMember` (the list pages' rule). Viewing needs `settingsRightAdmin`.
- In this plan each event definition carries the Welcome text part (`settingsEditTextPart`) as a stand-in whose wait text is never shown, because no Set action exists until plan 20-08, which swaps in the event family's own text part.
- The message editor bullet of AGENTS.md documents plan 20-03's hooks here, with their first production user (D-25).
